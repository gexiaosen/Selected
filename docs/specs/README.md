## 数据与存储

- **裸 SQLite + 两层自封装**（`SQLiteReader`/`SQLiteWriter`），不引 SwiftData / Core Data / GRDB。
  因为要显式控制 `PRAGMA quick_check`、`sqlite3 .backup`、`journal_mode=WAL`、`busy_timeout`、幂等迁移与跨进程共库；
  这些在框架里都是"隐式行为 + 额外防御"。GRDB 是唯一值得考虑的替代，但现有封装已稳定且有并发契约覆盖，换是纯成本。
- **WAL 库不能直接拷主库文件** —— 会静默丢数据（实测主库 0 行 / 实库 1 行）。备份一律走 `sqlite3` CLI 的一致性快照。
- **只读连接跨线程会 SIGSEGV**。靠「主线程共享只读 / 后台各自 `makeIndependent()`」这条约定，不是类型系统兜的。
  凡是把后台路径改成复用 `SQLiteReader.shared` 的"简化"，都会把崩溃藏进偶发路径 —— 设置页那次卡顿修复就以此为前提。
- **「独有数据库列」必须独立于版本水位**：`ensureSchema` 在 `schema_version >= SCHEMA_VERSION` 时直接 return，
  ALTER 混进迁移清单会被永久跳过（老库永远拿不到）。走 `DBBootstrap.ensureSwiftOnlyMigrations`，无条件跑、幂等。
  回填粒度到日，查不到保持 `NULL` 并回落当前激活版本 —— **不用哨兵值**。
- **不做日锁（first-write-wins）**。信号由本地确定性计算产生、没有"投递"概念，`signal_classes` 主键本就是 `(date, code)`，重跑就是要重算。
  移植过来会让 14:15 的 `pulse` 永久盖掉后面的 `consensus`，且不报错。
  ⚠ 前提是"信号来自本地计算" —— **一旦引入外部信号源，正确形态是在入口做幂等**，届时重评。
- 夹具 `engine/tests/fixtures/` 里被纳管的那几个是**一次性手工捕获、不可再生**的结构样本；删掉 = 仓库坏了，不是"清了缓存"。
- **指标筛选是多条件 AND（最多 6 个），一次 SQL 完成**：`IndicatorSnapshotStore.screen(rules:…)` 把各规则的
  `whereSQL` 括起来拼 `AND`、每规则一个 `valueSQL` 结果列；任一规则要前一快照日时**只加一个** `p` join；
  排序在 SQL 的 `ORDER BY`（`NULLS LAST`）里做 —— **不许只重排前 300 行**冒充全局排序。
  任一 id 未知 → 整体返回空，**不静默丢条件**（少一个条件等于筛出另一批股票）。
- **静态数据表一律用 `SharedDataTable`**（`Views/Components+DataTable.swift`）：表头 11pt/28、行 30、
  数字右对齐、只有行间 1px 发丝线、**无斑马纹、无列竖线、无表头底色**。原生 SwiftUI `Table` +
  `alternatesRowBackgrounds` 已全部清掉（复盘/历史迭代/调优/三轮对比四处，2026-10-26）；别再引入。
  列宽固定列之外按「名称 2 : 其他 1」摊剩余宽度（表头与行共用一份计算），不许只让名称列吃满。
  ⚠ **但"均分剩余"不是终点**（2026-10-26 老板在选股结果页打回）：均分让 4 字的窄列与 7 字的宽列一样宽，
  列内两侧全是空白。正确形态 = **列宽按内容实测（`NSString.size`，表头与所有单元格取大者 × 1.35）+
  富余只进相等的列间隙（封顶后再按比例回摊）+ 每列内容与表头居中**。
  宽度输入必须量**窗口驱动的那一层**（如 `FitScrollView`），不许量卡片/表头/行 —— 定宽行会把父容器
  反向撑宽，窗口缩小时永远回不去；行本体还要 `.frame(maxWidth:.infinity, alignment:.leading)` 钉左，
  否则行宽 < 卡宽时整行被居中，与表头错开。
  ⚠ 进不了组件的两处（板块矩阵要 `Grid`、指标筛选结果表要横向滚动 + 表头排序按钮）**也必须读同一套
  `TableMetrics` / `TableRule`**，不许自己写 `rowHeight = 24` —— 护栏 `table_geometry` 查三件事：
  几何常量只许 `Components+DataTable.swift` 定义一份、`.tableStyle(`/`alternatesRowBackgrounds` 不得回潮、
  在册表格页（`_TABLE_PAGES`）必须真的引用 `TableMetrics`/`SharedDataTable`（只定义没人用=名存实亡）。
- **表格的表头与数据必须来自同一份列宽/同一个 `Grid`**：`BoardView` 的板块矩阵曾用两套 HStack（表头无 padding、
  数据 5pt）导致整体错 5pt；2026-10-26 改成同一个 Grid 后列宽只有一份。行数也别用视口估算——
  左卡会被右侧详情卡撑高，底部会空出几行；用**卡片实测高**倒推（`matrixCardH`，上限 +8 行防自激）。
- **筛选结果表必须带「收盘价 + 当日涨跌幅」两列**（收盘来自快照 `close_value`，涨跌幅用前一快照日收盘算；
  没有前一日 → `—`，不硬造 0）。只有指标列的表在宽窗口里必然剩一大片空白 ——
  2026-10-26 老板看完原型明确指出"后面很空"，加这两列既填满又有用。
- **结果表宽度：铺满分摊**——固定列（# / 代码 / 收盘 / 涨跌幅）之外，名称 140–300pt、指标列 72–260pt，
  按比例吃掉剩余宽度；列数过多/窗口过窄时横向滚动兜底。禁止只让名称列吃满（会出现"一列特别空"）。
- **勾选面板必须显示每条规则的当日单独命中数**（一次 `SUM(CASE…)` 出 22 个数）。这些条件会互相矛盾
  （上穿均线 vs 超卖），实测 2026-10-23：`EMA上穿 + RSI超卖 = 0`，而两者单独分别 893 / 802 ——
  没有单独命中数，用户只能靠撞 0 才发现。0 命中页要给"去掉哪一条能有多少只"的实查建议。
- **重算完成后的页面刷新必须观察 `Store.indicatorSnapshotRevision`，不能只观察覆盖只数**：
  周期改动触发的重算前后，覆盖只数通常都是 5217 → `onChange(of: coveredCount)` 永远不触发，
  页面会一直显示旧周期的命中数（2026-10-26 修）。
- **设置面板里的 `osc.*`（超买超卖线）只服务个股详情页**（`StockDetailSheet` 的 `oscConfig()`），
  对筛选结果零影响 ⇒ 在筛选页面板里必须折叠并明示"不影响本页筛选"，不许和判据阈值混排。
- **历史日不得触发快照重算**（今日 bar 只能由当日收盘行情合成）：周期改动在历史日只保存，
  面板文案要写清"回到最新交易日后生效"，不要先承诺重算再弹"不可重算"。

## 参数系统

- **参数中心只放"真的会生效"的旋钮**。6 个被上层阈值支配、改了没反应的键已从 schema 移除（只能改 `FACTORY_PARAMS` / 出厂 JSON），
  回归锁 `ParamSchemaContractTests` 钉住它们不得回去。⚠ 引擎里那些 `?? 0` / `?? 12` 的**回落值本身就是错的**，要修得两侧一起修。
- **新增引擎侧开关一律走「工厂参数 + 读取处回落默认值」，不声明为 schema 项。**
  声明成 schema 项会让所有存量参数版本立即非法（`validate` 对必选键缺失一律报错，这是防拼错静默失效的闸门），
  表现为"用户改完参数保存 100% 被拒且库里修不好"。给出厂 JSON 补键也修不了用户自存的版本。
- **json 型参数的必填子键是真闸门**：`ParamSchema.requiredJSONKeys` / `requiredSubKeys` 要求阈值表的 `le1/le2/le3/gt3` 存在，
  所以"改阈值"= 删必填键 = 保存被拒 ⇒ 结构化编辑器**阈值只读、只增档不删必填键**。
  每个 json 参数都必须在 `ParamTableSpecs` 有条目，否则退回裸文本框 —— 覆盖性测试专门防这个静默退回。
- **出厂行落库后即用户数据**：`ensureBuiltinSeeded()` 只补缺失行、**永不覆盖**；唯一的覆盖入口是参数中心的
  「恢复出厂设置」（显式 destructive 确认）。墓碑机制保留（删过的出厂版本启动不复活）。
- **版本生效日期**存在 `param_versions.effective_from`（见上「独有数据库列」），评估池按 `sel_date` 反查当日生效版本；
  **不做"按当日版本分别评估"** —— 会让不同样本跑在不同基线下、指标不可比。
- **参数标定必须按 `reviews.scan_mode` 分口径，且两把尺子都看**（2026-11-02 深迭代实测）：
  `replay_close` 的量比是**全日**量比、`live` 是**盘中时点**量比，阈值不可互换；把 12k 条回放样本和
  1.3k 条 live 样本混算出来的"最优带"是两种口径的平均数，**两个都不对**。
  尺子也有两把：`stock_outcomes.disc_*` 用统一政策 `discipline_target_pct`（出厂 1.5%，**调优器读这套**），
  `reviews.four_layer_json.disciplined` 用**每只票自己的目标价**反推（实盘约 +3.0%，**界面显示这套**）；
  同一天两者实测差 10~20pp —— 只看前者会得出"界面在骗人"的错结论，标定用前者、验收必须以后者复核。
- **打分项的方向只在"双口径同向"时才改**；无区分度的维度**不许拿来砍数量**。
  实测换手率 `[4.2,10.5]`、`form_filter.pass_threshold` 在两口径上的次日命中率差都 <1pp（等于噪声），
  而量比（58.3%→38.2% 单调）、5日均量倍数、距低点、MA 偏离、5日累计（U 型）五项**现行方向是反的** ——
  这解释了为什么一档命中率反而低于三档。**反过来说：换手率与形态这两族键既然没有区分度，就不能拿来当数量闸门** ——
  收紧它们只会随机减少样本，命中率不动（本轮因此**没有**动它们）。
- **没有"当日不选股"的硬开关，日级闸门只能用分值实现**：`exclusion.market_*` 三项只决定 `ratio_ok/sh_ok`，
  进而给 `market_ok_ok/only` 加分，是**整日平移**（同日内不改变排序）。把加分放大（5→18）后，
  弱宽度日实测自动从 20 只/日缩到 2.4 只/日，等效于闸门。**要真"空仓跳过整轮"得改代码，不是加参数** ——
  且按上面的 schema 规则，新增引擎侧开关不能声明成 schema 项。
- **`num_pair` 的「区间倒挂」校验挡住了"负加分"的表达**：`scoring.bonus.vol_mult_high = [1.8, -8]`
  会被 `validate` 判成下限大于上限而**拒绝保存**（它是通用 pair 校验，不认识"阈值在前、分值在后"这一族）。
  要表达"高倍放量不给分"只能写 `[1.8, 1.8]`（分值≈阈值，等价 0 分）；**真要扣分得走 penalty 表**。

## 引擎口径

- **涨跌家数严格按涨跌额符号**（`>昨收`=涨 / `<`=跌 / 相等=平），**没有 ±0.1% 死区**。
  死区等于给不同价位定义不同的"平盘"（`12.20→12.21` 界面红、统计算平），实测把平盘数抬高约一倍；标准口径都按符号。
  ⚠ 历史 `scan_rounds.market_env_json` 存量行仍是死区口径，**不回填**。平盘里不剔停牌：语义上记平是对的，量级也极小。
  `ratio` = 涨 ÷ 跌，跌为 0 取 999，是评分输入。
- **四层胜率走势的周聚合是简单平均** —— `reviews.four_layer_json` 只存胜率不存样本数，权重拿不到，
  所以口径**必须写在界面副标题上**（护栏 `winrate_trend` 钉默认 20 / 阈值 120 / 副标题）。
  不按自然日聚合（桶跨周末）；聚合行日期取该周第一个有样本的选股日（周一可能无样本）。
- **历史回放口径不可能忠实**：它是收盘价回测不是尾盘重放（分时不可回溯，尾盘 12 项整块跳过）—— 这是功能天花板，不是实现缺陷。
  所以回放行必须打 `scan_mode`，调优器默认只用 live；隔离规则「同一天已有任何 `scan_rounds` 行 → 整日跳过」。
  `change_pct`/`amplitude` 一律自算，不混用源字段（除权日会悄悄分叉）。
- **唐奇安「创 20 日新高」必须与前一快照日的上轨比**（`t.close_value > p.donchian_channel_upper`）。
  当日上轨 = 含当日 high 的 20 日最大值，`close > 当日上轨` 数学上不可能（最多相等）—— 旧规则在 5217 只里恒命中 0。
  改回当日上轨就是恢复一个永远筛不出股票的按钮；`valueSQL` 也必须用 `p.` 上轨，否则超轨% 恒为负。
- **「删除参考实现」的代价要说准**：改**引擎计算口径**（过滤链、打分合成、档位边界、信号分类、落库四表、四阶段输出）
  **没有任何自动化能发现**，只剩纯函数单测 + 人工看结果。这是用户第三次要求清理时明确接受的取舍。
  保留的只有两个随包 JSON 的 Swift 生成源 + `SchemaExportTests` 逐字节断言（挡"忘了重新生成"）。

## 「只展示、不进评分」这一族

详情页里 K线形态、六条策略、超买超卖、技术指标、技术面判据、资金流向、基本面、涨停统计、龙虎榜、回撤风险、
次日区间 —— **全部只展示，不进评分、不进筛选**。三条理由，每一条都还会用到：

- **零标定 = 凭直觉给分**。清单/README 抄来的判据没在本地样本上验证过，就不该影响选股结论。
- **同源重复计分**。已有维度（如尾盘量能本就是评分输入）再做一遍"抢筹"加分，等于同一证据计两次。
  这类卡片上**不要**写"只展示不参与评分"—— 它明明参与，写了就是假话。
- **改评分的代价当时还叠着"夹具全红"**，那条依据已随对账删除而消失；现在只剩上面两条，仍然成立。

配套口径（都是踩出来的）：

- **算不出来 ≠ 没有**：样本不足、分母为 0、`MD==0` 一律返 `nil`，"未评估"与"中性/未命中"分开显示。
  把"算不出"折成 0 或 50 就是伪造结论；`"-"` 哨兵在解析/落库/读取/展示**四层**都不许折成数字。
- **引擎侧日K默认只有 65 根**，需要 250 根的判据（回踩年线、低 ATR）在引擎侧根本算不出来，只能落详情页（500 根）。
  用"有 250 根"当上市天数会因长期停牌失真，改接东财 `f26` 拿真实上市日。
- **筹码分布（CYQ）只展示**：窗口 250 根摊到 100 档网格，流通股本按「成交量÷换手率」优先、回落「市值÷现价」。
  浮点做网格比较别直接用 `JSONSerialization` 的 `Double`（长小数会变形）。
- **回撤与距高点是两个方向**：`distFromHigh` 在上涨侧、最大单日跌幅在下跌侧，复用会给出相反结论。
  窗口按**最近 60 个交易日**（需 61 根 bar），阈值 `0.6` 读作 **60%**。
- **不做读屏无障碍**（产品决策，代价 = App 对读屏用户不可用，已确认接受）。
  读屏只能靠人工听 VoiceOver 验 ⇒ 永远挂在验收清单里验不掉，而加回来不会让任何测试变红 —— 才配一条护栏（`a11y_absent`）。
  ⚠ **差点误删的两类**：`@Environment(\.accessibilityReduceMotion)`（驱动 `motionAware`，是功能）、
  `accessibilityHighContrast*`（系统高对比度外观，属配色）。给一个没人验的功能补代码 = 签一份长期维护合同。
- **概念分类不做**。概念成份每周加删，用当前清单回放历史 = 用未来信息，直接冲突回放纪律。
- **所属行业徽章已下线**（2026-10-28）：数据只有东财 `clist` 的申万 `f100` 一条路，
  而全市场 56 页分页在按 IP 限流下几乎不可能整轮成功（详见记忆与 `data_source_logs`）；
  它本来只做详情页展示、不进任何筛选与评分，故整条链路删除（含 `stock_industry` 表与上市日期 `f26`）。
- **北向数据不做**，交付物就是这条否证：2024-08-19 起取消每日披露 —— 东财 `kamt` 北向 `dayNetAmtIn` 恒 0.0、
  持股报表只有一期季度快照且"变动"列全 null、额度表只有上限没有已用。换港交所/同花顺/雪球结论不变（同样停披露 + 新 provider）。
  **收益为零（数据不可得），不是"没做"。**

## 数据源与网络

- **东财 `push2*` 限流的根因是出口 IP**，不是代码。对照实验：同一 URL 换网络返回正常。
  导火索是回放的全市场日K下载（并发 × 每票一请求 × 重试）—— 它是全项目唯一漏走全局限速器的 K 线路径。
  ⇒ 新增任何批量抓取都必须过 `throttleAfterNetwork()`（护栏 `push2_throttled`）。换 host 不解决问题（同族连坐）。
- **失败提示要给出路，不只给原因**：疑似限流时在"未刷新"后追加「换网络或稍后再试」。
  判据是 Core 纯函数 `DataSources.isSuspectedThrottle`，**刻意保守**：超时 / 4xx·5xx / 截断 / 空响应体各有根因，不归限流
  （误报会把人引到错误的修复路径）。⚠ **匹配系统错误字符串的判据必须中英都认** —— 中文 macOS 下
  `localizedDescription` 会把 -1005 本地化成「网络连接已中断」，首版只写英文串 ⇒ 静默漏判。病根在判据侧不在文案侧。
- **字段含义必须用算术恒等式在真实响应上校验**（各家文档不可信）：市净率 = 价 ÷ 每股净资产、ROE、资产负债率逐条对上才落库。
  含义不明的字段落库 = 埋雷，显示即编造。
- **整表替换的两张表**（`securities` / `stock_fundamentals`）都要有**下界护栏**（少于阈值不覆盖旧数据）
  + 完整性检查；数值列一律不给 `DEFAULT`（`NULL` 才是"源没给"）。两个数据源不蹭同一次抓取，否则刷新与演进互相绑死。
- **外部时点数据必须落库**（资金流、涨停池、龙虎榜）—— 不记就取不回，历史标定唯一的前提就是它。
  但**前瞻字段一律不存**（`D1/D2/_CLOSE_ADJCHRATE`、上涨概率等供应商加工值 = 时点污染）。
- **龙虎榜**：一天 3 次请求够（放大 `pageSize` 单页取完）；主键不能用 `EXPLANATION`（文案随供应商修订，用稳定规则码）；
  席位表无可证明的自然键且返回顺序非金额降序 ⇒ 同事务先 `DELETE WHERE trade_date=?` 再整批插。
  `*_RATIO`/`*_RATE` 是**百分数不是 0–1 小数**。⚠ **不做 `securities` 过滤** —— 北交所会合法上榜，展示侧同样不能过滤，否则整卡消失。
- **涨停池源只覆盖最近约 10 个交易日，补不了历史**；日期由**请求日期盖章**（响应 `qdate` 恒为服务器当天）。
- **同一动作不留两条入口**：自选页表头的「+」弹窗是搜索框的严格子集（同池、同模糊匹配、同代码直加、同指定分组），整族删除。
  加号没有独占能力，保留只会再养一套重复实现。

## 调度与自动化

- **"该不该跑、何时唤醒"必须是 Core 纯函数**（`ScheduleEngine.decide`/`nextFire` 共用同一套 `Disposition`），
  漏跑 `missed` 是一等状态、要显式通知。否则验收只能靠"跑几天看看"。
  **补跑窗口不许放宽成"当日剩余时间"** —— 会把单轮脉冲伪造成"三轮持续"，绕过"仅三轮持续才买"的核心纪律。
- **状态判定只读结构化字段，不读文案**（护栏 `sched_no_text_state`）。
- **告警判据必须落库、评估必须搬出视图**。挂在 `WatchlistView` 的 `.task` 上 ⇒ 切页即视图销毁、静默失效；
  触发状态放内存 ⇒ "单次 / 每日重复"语义根本不成立。全 App 只留 `AlertMonitor` 一个行情轮询方。
- **盘中值只进内存，不落库**（昨涨停情绪、领涨板块 TopN）：写了就和收盘定稿分不出来。看板在定稿后**优先读 DB**。
  历史日不许显示实时指数（会混日期）。
- **看板默认落当天要改 `refresh()` 的目标**，不能只改 `viewDate` —— 后者会被"未锁日期则跟随最近有数据日"覆盖，
  表现为"打开是今天、刷新又回昨天"。
- 持仓当日盈亏 = `Σ(现价 − 昨收) × 股数`，当日盈亏率分母用**昨收市值**（`Σ 昨收 × 股数`，仅计有昨收的票）
  —— 券商"当日收益率"口径，用总成本当分母会把持仓以来的涨跌摊进今天、日内涨跌幅被稀释。
  已知口径缺口：没有建仓日期 ⇒ 今天新买的仓位也按昨收算；不含已实现盈亏与分红。
- **默认分组 = 所有分组的去重总量视图**（不是物理归属）：从默认组"移入别的组"在默认组这一侧退化为复制，所以默认组恒置灰。
  语义要落在 Core（`moveWithin`），只在 UI 拦等于没锁住。无需数据迁移。
- **收盘后任务的时刻要按「上游什么时候发布」定，不是按「数据什么时候定稿」定**，
  而且**起点 + `retryIntervalSeconds × (maxAttempts - 1)` 必须覆盖实测的最晚发布时刻** —— 只压线不算改好。
  资金流 15:20 连挂 7 个交易日的实测：新浪当日那一行 15:24 前还没发布（17:25 已有），
  而重试策略是 `retryIntervalSeconds=120 × maxAttempts=3` ⇒ 15:20/15:22/15:24 四分钟内打完转 `missed`，
  **25 分钟补跑窗口从未被用到**。所以"收盘定稿"（15:00）只是必要条件，不是充分条件 ——
  交易所/新浪的**发布延迟**才是决定数（龙虎榜 17:30 就是这个原因，只是当时没人给资金流算这一笔）。
  ⚠ 挪时刻前先确认下游：`stock_fund_flows` **没有引擎侧消费者**（只有个股详情页读），
  所以晚 40 分钟不影响任何判定；有消费者的任务挪之前必须先回答同一问题。
  ⚠ **推断值要被量得替换**：第一次挪用的是 16:00（由"15:24 无 / 17:25 有"推出的安全值，当时没量到边界）。
  三天连续读数证明它**压线**：成功时刻 16:04:09 / 16:02:05 / 16:02:19，而预算终点正好是 16:04
  —— 11-03 差一秒当天就没数据 ⇒ 起点改到 16:05。
  ⚠ **补跑窗口救不了 `attempts` 耗尽**：窗口管"任务还能不能开始"，而三次打完是 `attempts` 上限先撞线；
  两者谁先到就按谁收尾，别把窗口当成无限重试。
- **每条抛错路径都必须留痕，收尾文案不许覆盖真因**。资金流的三道闸门里只有①②写 `data_source_logs`，
  ③日期闸门直接 `throw` ⇒ 库里 `fundflow` 这个 source **一条记录都没有**；
  而 `markRetry` 又把 `st.message` 整句换成"已重试 N 次仍失败"，真因只活在 `lastError` 一瞬间；
  这包的 NSLog 用 `log show --level debug` 也读不到 ⇒ 三条线索全断，只能靠人推。
  ⇒ 现在③补写 `not_ready`（带锚点日期与今日），收尾文案改成「真因（收尾原因，当日不再重试）」。

## 界面：AppKit 死路与几何

**这一节几乎每条都是"试过了，不通"。**

- **侧栏没有开合**（护栏 `sidebar_notoggle` 钉删除态）。开合是两族顽疾的共同根因：
  ① 动效逐帧重排整页（单帧 85~100ms）；② 展开时系统按"保持详情列宽"申请窗口宽度，把窗口撑大。
  ⇒ **拆功能比修护栏干净** —— 护栏追系统的程序化 resize 追不住（同一问题三次补丁全失败）。
- **动效本身就是这类卡顿来源**（两条独立实测：侧栏开合、切页交叉淡入）。
  交叉淡入要求过渡期同时渲染旧页与新页 ⇒ 双页并渲占满主线程，点击反馈排在重渲染之后，用户以为没点上又点一次。
  借鉴 flo-state 的"动画期冻结正文宽"机制**有效**（确实消除了逐帧重排），但系统开合是两段式（空白带闪烁 + 端点突跳），
  视觉仍不如硬切 ⇒ **维持硬切，此路永久关闭**；唯一出路是自定义窗口壳，与"尽可能用原生"冲突。
- **`.tint` 改不动 macOS 侧栏的选中胶囊**（`selectionTint` 在本机 SDK 不存在）。层级实测：
  `content.background` 画在系统胶囊**之下**（盖不住），`listRowBackground` 画在**之上**（能盖住）。
  ⚠ **决定性障碍**：选中后 `List` 拿键盘焦点，系统 emphasized 态**强制把选中行前景画成白色**，压过一切显式
  `foregroundStyle` ⇒ 灰底配白字不可读。唯一解是 AppKit 私有层级探针 —— 为换个选中底色不值当。**黑白灰侧栏整体回退，别再重提。**
- **红绿灯的 18pt 是手摆出来的**：`.unifiedCompact` 空带只能给到左 12 / 上 13.5，`toolbarStyle` 与 SwiftUI 的 titlebar
  修饰都改不动 ⇒ 装完带再整体**平移** `standardWindowButton` 的 frame（逐个摆坐标会破坏系统定的间距）。
  `NSTitlebarView.layout()` 每次重排都摆回去 ⇒ 必须挂 `didUpdate`/`didResize` 自愈观察器（幂等、按窗口去重）。
  ⚠ **量算基准必须是容器内坐标**（`container.bounds.height − frame.maxY`）。用 `convert(_:to: nil)` + `window.frame`
  会差一个标题栏高，量出 `topGap = -63`、三颗灯被推到窗口外（症状是"红绿灯消失"而不是"位置不对"）。
  ⚠ **开窗不跳的正确顺序 = 先藏灯 → 上屏后淡入 → 同一轮立刻补摆**：`alphaValue` 0→1 本身会**同步触发**
  标题栏重排（实测淡入那一毫秒按钮被摆回 12/13.5）。先摆位再淡入会被这次复位顶掉，下一轮补摆就是
  肉眼看到的"刚打开跳一次"（0.5.101 实测）；淡入后紧接着同轮 `pinTrafficLights`，两次都发生在下一次绘制之前。
  已经可见的窗口不藏（晚挂载时闪灯比跳位更糟）。
- **`NSHostingView` 里想让某片区域能拖窗口，三条"更原生"的路全部不生效**（命中链探针证实）：
  ① 挂真 NSView + `mouseDownCanMoveWindow = true`；② 换 `NSVisualEffectView`；③ `mouseDown` 里 `window.performDrag(with:)`。
  ⇒ 只能自己接管拖动。**且 `mouseDragged` 必须用 `NSEvent.mouseLocation`**，用 `event.locationInWindow` 会自激（它随窗口移动而变）。
  ⚠ 拖动区只能挂 `.background(WindowDragStrip())`；改成 `.overlay` 会把页栏按钮的点击整排吃掉。
- **闭包式 `addObserver(forName:)` 返回的 token 不 remove 就永久持有**，`makeNSView` + `updateNSView` 双路都会挂 ⇒
  按 `ObjectIdentifier(window)` 去重登记，`applicationWillTerminate` 统一移除。
- **那条忽有忽无的横条是空工具栏的 hairline**。`titlebarSeparatorStyle = .none` 无效（它是窗口级标题栏分隔线，三态都画）、
  `titlebarAppearsTransparent` 只压得住聚焦态。唯一有效的是 `.toolbarBackground(.hidden, for: .windowToolbar)`。
  ⚠ **别用 `.toolbar(.hidden, for: .windowToolbar)`** —— 会把红绿灯宿主一起摘掉。
  带顶出来的空白由玻璃层 `.ignoresSafeArea()` 铺到窗口顶 + 详情列负 padding 回收（两列内容自己不出 safe area）。
- **窗口只有一种底，内容直接坐在上面**：全窗一层玻璃（`WindowGlass` 挂在两列容器的 `.background` 上，
  底下垫 `Tok.windowBacking` 半透明底衬）—— 红绿灯带、侧栏导航、内容区共用这一块；页面内容**不再垫任何面板底**，
  页面自己的 `.padding(16)` 就是内容与玻璃之间唯一的距离。
  旧结构是"空工具栏带 + `-37` 负 padding + 不透明 sticky 页栏 + 底边 Divider"四层补丁，每层都在补上一层的漏；
  后来加过"侧栏独占材质"（三种表面）与"内缩内容面板 + 描边 + 三层阴影"（两种表面），老板实机逐版看完否掉：
  「只要两种，一个大的作为底色」→「其他页面也全都去掉，内容直接放」。
  ⇒ 页栏现在只剩一块透明拖动区（`WindowDragStrip`），**没有**自己的底 / `zIndex` / 底边线。
  ⚠ 别拿系统材质（`.regularMaterial`）当"与窗口同调"—— 它解析成系统色（浅 `#F1F1F1`）比窗口底亮约 5 级、
  且不跟窗口底，会在整页里显得孤立。
- ⚠⚠ **窗口底只准一层 SwiftUI glass**：再叠 `NSVisualEffectView` / behindWindow 材质会改变透明度与选中态观感；
  当前实现是 `Tok.windowBacking`（半透明底衬）+ `Color.clear.glassEffect(.regular)`，挂在两列容器的 `.background` 上。
  玻璃层挂在 `.background` 上，不摆成与两列平级的兄弟层；侧栏列自己不再挂任何背景。
- **窗底基色必须有一档中性下限**：底衬实际是半透明（浅 0.74 / 深 0.80），但基色不能贴纯白/纯黑，
  否则桌面一白/一黑就把窗口洗平，卡面与底的分界消失
  （原型实测 ΔL 只剩 6 级 / 1.05:1）。⇒ `ThemeColors.neutral(...).glass` 两枚（浅/深），方向与带宽由 `theme` 自检第 8 组钉死；
  判据是**双向**的（浅档玻璃暗于本档中性底、深档亮于），且必须验**纯白壁纸**那一档，只测默认桌面等于没测。
- **卡片边界不许靠颜色单撑**：卡面是整窗玻璃上的极淡中性灰（浅 0.04 / 深 0.055），
  分界由 0.5pt hairline 撑；要拉到 3:1 玻璃就会发灰发脏 —— 有意取舍。
- **侧栏 144pt 是硬约束不是审美**：底部可用宽 = 144 − 36 = 108pt，要放下调度行 + 自绘外观三档（70pt）+ 齿轮（26pt）+ 8pt 间隔 = 104pt；
  试过 152（多给内容 8pt）⇒ 底部控件被挤。**收侧栏宽度前先重算这条。**
- **窗口初始尺寸只认 `.defaultSize`（挂 scene）**，`minHeight` 不是高度旋钮（内容理想高 ≤ min 时窗口开在理想高）。
- **改窗口默认尺寸必须同时换"一次性重置"标记**（`resetMainWindowFrameOnce` 那类），否则 AppKit 存的旧 frame
  永远覆盖新默认值 —— 主窗口与设置窗口各踩过一次。
- **18pt 是一整套边距，不是七个孤立数字**（红绿灯、侧栏首行、底部三件、右上按钮、轮次栏）。两个具体成因值得记：
  ① 轮次按钮偏右 22pt 不是 padding，是写死的 `.frame(width: 344)` 让 segmented 内容**居中** ⇒ 改 `.fixedSize()`；
  ② 侧栏图标左缘 = 列左 10 + pill 内缩 8 = 18；改用 `SidebarTab` 后不要再加 leading 偏移。
- **侧栏底部可用宽是算死的**：144 − 36 = 108pt；调度行 + 自绘外观三档（70pt）+ 齿轮（26pt）+ 8pt 间隔 = 104pt。
  改列宽、改边距、加底部控件都要重核这条，否则整行被压扁。
- **`ViewThatFits` 选中的子树在深色冷启动下会按系统外观解析 `.primary/.secondary`**（整卡黑字压在深底上，页面其余文字正常）。
  ⇒ 从父视图显式注入 `@Environment(\.colorScheme)`，别删。
- **配色档位已移除（2026-10-30）**：原先 `Color.adaptive` 在构造时固化 hex，换档必须靠 `.id(档位)` 重建，
  而 `.id` 只能挂详情列（挂整棵 shell 会让侧栏 `List(selection:)` 的选中胶囊变纯黑块）。
  现在只剩单套色值、`Sem/Tok` 是 `static let`，不再需要任何 `.id`。
- **启动参数域（`-key value`）优先级高于持久域** ⇒ 用参数域钉初值，会让运行中对该键的写入"读不回来"，
  依赖它的观察与重建整条链路静默失效。要钉初值就钉在**与被观察的同一条通道**上。
- **焦点环**：`.focusEffectDisabled()` 只关视觉、`.onKeyPress(.return)` 键盘路照常
  （鼠标点击会把键盘焦点移到行上、留下常驻蓝框）。
  ⚠ 整行包 `Button` 会把 label 里的 `.focusable()` 踢出 Tab 循环、也收不到 Return，而鼠标照常能点 —— 只断键盘路，最难自己发现。
  验证法：临时开 `AppleKeyboardUIMode=2` + AX 程序化聚焦 + CGEvent Return（验完恢复）。⚠ 合成 CGEvent 的**鼠标移动**不触发 `.onHover`。

## 详情页与图表

- **`Card` 的 content 是饿求值，详情页不动它**。实测一次 body 求值纯计算合计 4.82ms（最坏样本），与设置页的 225ms 差 47 倍
  —— 为 5ms 改全局共享组件不值，而且 `content` 从"已求值"变"闭包"会改变**所有**调用点的求值时机与 `@Observable`
  依赖登记范围，本项目无 UI 自动化，改错只能人工发现。⚠ 也**不要**给详情页单独做"惰性卡片" —— 那是在共享组件旁边长出第二套卡片。
- **设置页卡的那三处**：`ForEach` 的 id 不许是整个 payload（6MB 候选每次 body 重哈希 = 225ms，护栏 `foreach_id_payload`，
  无豁免、全站通用）；重 I/O 搬后台（首读显示"正在读取…"约 1.1s 是**明码标价**的代价）；
  ⚠ `.offset` 当 id **不能照抄到会原地增删/重排的列表**。
- **分时成交量柱全红，根因不在图表库、在喂进去的数据**：`open` 被填成"现价" ⇒ `open == close` 恒成立 ⇒ 判色永远走正色。
  折线读 `close`、Y 轴读 `high/low` 都正常，**只有成交量柱坏掉** —— 这类"半张图是错的"最难自己发现。
  修法是填对 `open`（= 上一分钟价，首根昨收），两个消费方同时得到正确方向，库一行不动。
  胶囊要**单独**按"相对昨收"判色（A 股惯例是当日涨跌，不是最后一分钟环比）。
- **改默认图表周期会逼出隐藏依赖**：六张按"一根 bar = 一个交易日"定义的卡原先都读 `kline`（图表当前周期），
  默认改分时后 `kline` 为 `[]` ⇒ 卡片整批消失、「放量大跌」永远判不出来，**不报错、不崩、全部测试绿**。
  正确做法是这些卡各取所需的独立日K，而不是让用户切回日K。
- **涨跌比必须三段（涨:平:跌）**：A 股平盘家数在窄幅震荡日可以上千，只显示两段会让人以为总数对不上。
  比例条抽成单一组件 `BreadthBar` 供看板与选股结果共用 —— 两处各写一份必然漂。
- **信号分类用水平堆叠条，别换回环形图**：扇形角度比不出大小，12 只里 8 只脉冲 = 一个大棕块。
  堆叠条的三条通道（数字压在自己那段上、段序 = 强度序、段间缝）与 `BreadthBar` 同一套理由。

## 文案与反馈

- **`Text` 有两个重载**：`Text("…**粗**…")` 走 `LocalizedStringKey` 会解析 Markdown（真粗体），
  `Text(变量/拼接)` 走 verbatim ⇒ 显示**字面星号**。引擎侧 12 行属于后者。
  展示层 `TextMarkup.toCJK` 现在的作用是**历史数据兼容层**（`compare_reports` 里旧轮次落库的 JSON 仍含 `**`）。
  何时可删：确认历史轮次不再回看，或做过一次落库文案迁移。
- **护栏不许用文件/行号白名单**（新加一行就静默通过、一改就漂）；用**同行标记**逼作者当场写理由。
- **toast 的档位必须由调用点显式表态**，不许按 message 关键词自动判（"含'失败'→error"：文案拼接会变、不可测，判错就是绿底的失败）。
  只 `.key` 窗口渲染（两扇窗口共用同一份 `ToastCenter` 数据，并排时会各画一条）。
- **按钮只有几个角色出口**（`btnPrimary/btnSecondary/btnDanger/btnDangerFilled/btnIcon`），语义色（涨跌/灯级/信号）**不上按钮** ——
  否则红色既表"上涨"又表"危险"。按钮只表达操作分量。
- **`alert` 与 `confirmationDialog` 混用是对的**：那几处 `confirmationDialog` 全是破坏性确认，按功能域有意区分，macOS 上不算错。
- **`nearly matches optional requirement` 警告必须当错误看**：`applicationShouldHandleReopen` 签名写成 `-> Void`
  （requirement 是 `-> Bool`）时 protocol 从不调用它，整条功能是死代码。

## 分发与系统

- **最低 macOS 26**：`Package.swift` 的 `.macOS(.v26)` 与 `Info.plist` 的 `LSMinimumSystemVersion` 两处必须同步（护栏 `version_sync`）。
  不可逆债 = 永久放弃 macOS 15 及以下装机量。换来的是删掉降级分支 + `defaultIsolation(MainActor.self)`。
  ⚠ 模块默认 MainActor 之后，**只被 `swiftc` 单独编译的自检文件（`Palette.swift`/`Tokens.swift`）不要再手写 `@MainActor`** ——
  那两个脚本不带这个 flag，写了就编不过，表现成"自检失败"而实际是"自检没跑成"。
- **1.0.0 起转为公开分发（GitHub Releases）**，但**不走 Developer ID + 公证**：那要 99 美元/年 +
  审核链路，换来的只是"首次打开少一次右键"。实际方案 = `Apple Development` 证书签名 +
  Sparkle EdDSA 校验更新包；Gatekeeper 首次拦一次，README 里直接写明右键打开。
  ⚠ **不要去用 ad-hoc 或自签"消掉提示"**：这两种身份的 designated requirement 与 cdhash 绑定，
  每次重建都会让 TCC（文件夹/通知）与钥匙串授权**从零再问一遍**；Apple 签发身份只认
  identifier + anchor apple generic + leaf CN，跨版本稳定。MiscKit 已实测过这条。
- **签名证书复用 MiscKit 的 Apple Development 身份**（`gexiaosen@outlook.com (AK52JP2G5T)`）：
  一张证书签多个 App 是允许的，省一张年签。代价 = **证书一年到期**，到期后新包身份变化，
  首次启动会重新问一轮授权；续期后重跑 `upload-signing-cert.sh` 更新两个 secret 即可。
  ⚠ CI 里必须显式验 designated requirement 含 `anchor apple generic`，否则证书导入失败会静默退回
  ad-hoc，发出一个"能装但授权全丢"的版本。
- **一把 Sparkle EdDSA 密钥跨 App 复用**（Selected 与 MiscKit 同钥）：Sparkle 官方明确支持一个
  签名密钥对应多个 App；`SUPublicEDKey` 相同不影响隔离。私钥只存在本机
  `~/.config/selected/sparkle_ed25519` 与 GitHub Secret `SPARKLE_PRIVATE_ED_KEY`，**绝不入库**。
- **只有 `v*.*.*` tag 触发发版 CI**，push 到 main 只跑回归：每次 push 都出包会让 Release 列表变成噪音，
  且 Sparkle 只认"版本更高"的包，频繁同版本重发会让 appcast 与资产对不上。
  ⚠ CI 必须校验 **tag == `Info.plist` 短版本** 且 **build 号严格大于上一版 appcast**，
  否则会出现"标签写 1.0.1、包内还是 1.0.0"或 Sparkle 判定"没有更新"。
- **1.0.0 的仓库历史是重建的单提交**：旧 653 条提交不推到公开仓库（含早期实验与本地路径），
  历史从 1.0.0 开始。⚠ 旧裸库必须在本机归档保留 —— 设计决策的演变只在那里可追。
- **DMG 布局复刻 MiscKit**：背景 600×360@2x + `.DS_Store` 烘焙图标位置（app 150,160 /
  Applications 450,160）。⚠ `.DS_Store` 与**卷名**绑定，改卷名（`Selected`）必须重跑
  `make-dmg-layout.sh`，否则 Finder 会按默认网格摆图标、背景也可能不显示。
- **许可选 GPL-3.0 而不是 Unlicense**：公开分发后要保留版权与许可约束；GPL 要求随二进制附全文
  （已放 `Contents/Resources/LICENSE.txt`），衍生分发须提供源码。⚠ 别再在文档/关于页自称 public domain。
- **通知左侧图标**：当初归因"macOS 26 系统限制"**是错的**（本机跑的是 27.0 beta，"26"来自 build 号前缀，当时没跑 `sw_vers`）。
  最后是一台机器 12 天没重启 + 一次系统更新，重启顺带生效 —— App 侧一字节未动。**作废的是理由，"接受现状"这个决定仍成立。**
  ⚠ 归因"系统行为"之前先 `sw_vers`；横向对比只是相关性，混淆变量没排除前别下"某类签名不行"的结论。
- **装到 `/Applications` 后必须 `xattr -cr` 再验一次签名**：`cp -R` 会带入 `com.apple.FinderInfo`，
  `codesign --verify --strict` 判为 detritus ⇒ 此前只在 `/tmp` 验过一次，失效是**静默**的（护栏 `install_signed`）。

## 测试与装置

- **三 target 分层是踩出来的**：`SelectedCore`（只许 `Foundation`/`SQLite3`）/ `Selected`（可执行）/ `SelectedCoreTests`，
  `Tools/*.sh` 统一链接 `SelectedCore.o`。原单一 target 手工列源码清单，一天踩三次漏补脚本，路径漂移还会让静态护栏**假绿**。
  ⚠ 自检脚本用裸 `swiftc` 编译 ⇒ 视图依赖一进来（哪怕只是调 `Components.swift` 的某个修饰符）那两个脚本就编不过。
- **"swift test 全绿" ≠ "这一片绿"**：`Tools/` 下的自检驱动是单独编译的，`swift test` 根本不覆盖它们。
- **参数标定驱动走真引擎，不留复刻公式**（`SelectedApp/Tools/param_calibrate_test.sh`）：
  分数一律由 `Screener.scoreStock` 现算（特征从 `picks.deep_info_json` 反序列化回 `DeepInfo`/`EngineQuote`），
  `--fidelity` 断言「用**产生该轮的那一版参数**重算 == 库里存的 score」，实测 13,122 条逐条一致。
  这条断言是**工具自己的防漂移闸门**：改过打分口径它立刻报红，而不是继续用旧公式给新参数下结论 ——
  引擎口径无对账（见「删除参考实现的代价」）时，这是唯一能把"标定脚本"与"引擎"绑在一起的东西。
  ⚠ 已删除版本行（墓碑机制永久删掉的出厂备选）对应的轮次**跳过并出声**，不许拿当前激活版的参数去重算旧轮次
  —— 那会把分叉伪装成一致。
- **`swift test` 必须 `--scratch-path` 指到仓库外**：本仓库目录受 macOS FileProvider 管理，新建目录会带
  `com.apple.FinderInfo`，codesign 直接报 `resource fork … not allowed`。
- **两套工具链交替写同一个 `.build/debug` 会让 Core 侧测试整片红**（`compiled module was created by an older version`）：
  打包脚本可能回退到 Xcode-beta 工具链，而回归用默认 Xcode。**不是代码问题** —— 先 `rm -rf .build/debug` 再判。
  长期解（统一工具链）没做，因为动工具链探测要重验整条签名/打包链路。
- **shell 变量紧跟全角标点会被吞进变量名**（`$VAR）` 在 zh_CN.UTF-8 + `set -u` 下 `unbound variable`）⇒ 一律 `${VAR}`。
  debug/release 分支不同可能长期不触发，别指望"跑过一次没事"。
- **一次只改一个变量再截图**。把两个改动绑在一起判生死，会把"其实有效的那个"误判成无效并整体回退 ——
  主窗口那条工具栏线就是这么被误判过一次。
- **量几何之前先确认前提**：量侧栏顶距要先确认首行就是第一行（List 会跨启动恢复滚动偏移，被滚掉一行就整体偏一行）；
  分清蓝/灰选中态必须保持 key window（失焦窗口的选中态也是灰的）。
- **快照出图是"验面的"，不是"验字的"**：`-appearanceMode dark` 只改 `NSApp.appearance`，实底会正确变深，
  但 `.primary/.secondary` 按环境 colorScheme 解析 ⇒ 整页文字黑压黑。深色图只用来核对色值/层次/缝，
  文字对比度一律以 `sem_contrast` 实算为准。
- **给"没人体感到的问题"预先做性能剖析，是本项目否决过的"为假设的未来需求设计"**。
  详情页视图构造开销至今未量化，处置是**真机观察到卡才激活**，激活后第一步量渲染层，别回头改 `Card`（4.82ms 已证伪那个方向）。
