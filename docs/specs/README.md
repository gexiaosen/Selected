# 设计取舍

记录几条会影响后续开发的非显然选择。实现细节看代码，这里只写「为什么这样定、哪些路别再走」。

## 数据

- **直接用 SQLite，不引 ORM**：需要显式控制 WAL、`busy_timeout`、一致性备份和幂等迁移；框架的隐式行为反而增加排查成本。
- **WAL 库不能直接拷主库文件**：必须用 SQLite 的一致性快照接口导出，否则会静默丢数据。
- **数据库是唯一不可再生的用户资产**：每次发版前自动归档，归档保留 5 份，恢复前先校验。
- **只读连接不跨线程共享**：主线程用一份，后台各自建独立连接；复用共享只读连接偶发崩溃。

## 策略

- **同一行情 + 同一参数 = 同一结果**：打分和过滤保持纯函数，便于复现和回归。
- **三轮扫描的时间必须依次递增**：轮次归属按相邻两轮中点切分，顺序倒挂会导致某轮永远选不出票，且界面看不出来。
- **不做历史口径对账**：只对指标、结构和参数契约做自动化校验；过滤链、打分合成、档位边界靠纯函数单测和人工复核。这是有意的取舍。
- **调优结果不自动应用**：历史样本评估只作参考，参数改动由人确认后另存为新版本。

## 界面

- **单窗口策略**：关闭主窗口等于最小化，不销毁；菜单栏常驻和调度不能因为关窗而停。
- **信息密度优先**：表格、分组和参数编辑都以一屏内可扫读为目标，不追求移动端式留白。

## 分发

- **仅 macOS 26+、Apple Silicon**：换取删除旧系统分支和统一工具链，代价是放弃 Intel 与旧系统用户。
- **DMG + Sparkle 自动更新**：更新包用 EdDSA 签名校验，不依赖 Apple Developer ID；应用本身未公证，首次打开需右键确认。
- **tag 触发发布**：只有 `v*.*.*` tag 才出包，普通提交只跑回归，避免 Release 列表被日常构建污染。

## 边界

- **公开行情源有频率限制**：批量抓取要限速；失败写入数据源诊断，不静默吞掉。
- **北向资金不做**：官方披露口径已变化，现有粒度和策略时间尺度不匹配，继续投入没有意义。
- **次日区间是统计参考**：不承诺收益，不作为唯一买卖依据。
