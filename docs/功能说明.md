# Selected 功能说明

本文档描述应用的**当前完整功能**。策略基线为 `late-day-stock-picker-2`（2026.9.10.r1），
全部业务逻辑由 Swift 原生实现，运行期不依赖 Python。

> 免责声明：本应用为信号分析与决策辅助工具，**不构成投资建议**，不含任何下单交易功能。
> 所有买卖决策由用户在券商端人工执行，盈亏自负。

---

## 一、产品定位

围绕「**尾盘买入、次日午前卖出**」的短线策略，把一次选股拆成可验证的闭环：

```
早盘预判 → 盘中验证 → 尾盘三轮选股 → 收盘复盘 → 三日迭代
                        ↓
                  次日真实结果回填（stock_outcomes）
                        ↓
                  参数调优 / 版本沉淀
```

核心设计取向：

- **纪律优先于收益**：宁可少选，不降低门槛；红灯日不给买入点
- **可复现**：同一份行情快照 + 同一份参数 = 同一份结果（纯函数单测锁定口径）
- **可解释**：每只票的分数、每项加减分、每条排除理由都落库可查

## 二、每日节奏

调度器用**单次定时器精确挂到下一个任务时刻**（14:50 的任务就在 14:50:00 触发）。
⚠ **任务时刻不在界面上改**（2026-10-27 起）：设置页只留总开关，时刻看**主窗口左下角「调度」栏**
的「调度任务」浮层（时刻 + 今日状态 + 失败原因）；要改时刻改 `SelectedCore/ScheduleCatalog` 出厂表。
到点后 25 分钟内视为补跑窗口，失败自动重试（最多 3 次，间隔 2 分钟）。周末自动跳过。

⚠ **三轮扫描时间必须依次递增**（第1轮 < 第2轮 < 第3轮）：轮次归属边界取相邻两轮的中点，
顺序倒挂会让边界也倒挂 —— 严重时**第 2 轮的归属区间不可达**（那轮永远选不出票），
较轻时**第 1 轮自己的触发时刻会被归到第 3 轮**，两种都**不报错、界面上看不出来**。
**2026-10-27 起时刻随版本固定**：设置页不再提供编辑入口（一年改不到两次，却要为它养一套
拒绝与回退 + 一个"恢复默认"二次确认 + 一屏 28 个同级块），所以这条约束现在**由出厂表保证** ——
要改时刻就改 `SelectedCore/ScheduleCatalog`，`ScheduleTimes.update` 的顺序校验**原样保留**
（将来重开入口时它还在）。⚠ 存量自定义仍生效：`ScheduleTimes.load()` 按 `key` 合并 UserDefaults，
撤掉的只是写入入口，不重置任何人已改过的时刻。

⚠ **第 3 轮的补跑窗口与其它轮不同**（有意）：它是当日最后一轮，收盘后行情就是当日最终状态，
故**手动补跑**时当日剩余时间均可补。但**调度器不享受这个例外**（超窗即记「未执行」）——
因为自动补跑取到的是**收盘价**，而同一天第 1/2 轮是**盘中价**，三轮持续信号会混进两种口径
且界面上看不出来。手动补跑时界面会**当场提示**这一点。

**超窗不会静默跳过**：任务到点后超出补跑窗口仍未执行时，会记为「**未执行**」终态 ——
侧栏底部调度圆点把对应点标红、悬停给出原因、写系统日志、并按需弹通知（仅当 App 当时确实在运行时才弹，
避免开机被历史欠账刷屏）。**系统睡眠唤醒后会自动补偿**：窗口内补跑，超窗显式记录。
菜单栏菜单会显示下一任务时刻；设置 → 自动化页会说明当前补跑窗口长度。
设计理由见 [specs/README.md](specs/README.md)。

| 默认时刻 | 任务 | 说明 |
|------|------|------|
| 09:30 | 早盘预判 | 基于昨日选股生成今日操作提示（窗口/目标价/止损价/仓位建议） |
| 10:00 | 盘中验证 | 预判 vs 实际走势，记偏差，更新策略命中率 |
| 14:00 | 第一轮选股 | 尾盘扫描 |
| 14:30 | 第二轮选股 | 尾盘扫描 |
| 14:50 | 第三轮选股 | 尾盘扫描（最终轮） |
| 14:50 | 全量判定 | 自选股三层判定（与第三轮同点） |
| 15:02 | 三轮对比 | 三轮交并集、信号分类、分档 |
| 15:05 | 收盘复盘 | 四层胜率统计与准确度归因 |
| 15:10 | 板块热度 | 收盘后抓行业板块当日截面（涨幅 / 主力净流入 / 涨跌家数 / 领涨股）并落库 |
| 15:15 | 涨停统计 | 收盘后抓当日涨停池（连板数 / 封板时间 / 炸板次数 / 行业）并落库；顺带算「昨涨停表现」（市场情绪，见 §十） |
| 15:25 | 指标快照 | 收盘后按全市场逐只算 22 个指标值并落 `indicator_snapshots`（指标筛选页的数据源） |
| 15:30 | 三天迭代 | 每 3 天生成趋势洞察与仓位建议 |
| 16:05 | 资金流向 | 收盘后抓全市场主力净额快照并落库（⚠ 新浪当日那一行的实测发布时刻是 16:02~16:04，而定在 16:00 时三次重试只到 16:04 就耗尽 ⇒ 起点挪到 16:05 留余量） |
| 17:30 | 龙虎榜 | 收盘后抓当日上榜记录与席位明细并落库（含回看补漏） |

任务完成后通过 macOS 通知中心推送；也可从菜单栏快捷菜单查看当前执行状态、手动触发。

## 三、选股引擎

### 3.1 八层流水线

一轮扫描依次经过（每层的结果都落库，可在「选股结果」页逐层查看漏斗）：

| 层 | 环节 | 要点 |
|----|------|------|
| 1 | 交易日判断 | 非交易日 / 节假日直接返回（不落库） |
| 2 | 全量行情抓取 | 腾讯批量 HTTP（500 只/批）；**两道闸门**：行情数 < 4000 视为数据源异常、报价日期必须为当日（防节假日误用昨日快照） |
| 3 | 大盘环境 | 上证涨跌幅 / 振幅 / 涨跌家数比 / 3 日趋势 / 连跌天数 → 红黄绿灯；**市场状态机**（多头趋势 / 多头回调 / 空头趋势 / 恐慌 / 修复反弹，MA 周期按 60/20/10 取历史能支持的最长）。**灯级判定完全不受状态机影响**；状态机只用于**门槛浮动**（卖出策略的目标价/止损价、自选的三条打分线，表在参数 `predict_rules.regime_thresholds`（**在参数中心可调**，见 §八；引擎缺键时逐态回落 `PredictRules.defaultRegimeThresholds`）），`UNKNOWN`（历史不足）时逐字不动。⚠ 涨跌家数的口径见 §3.1 下方注 |
| 4 | 硬性过滤 | 价格带、振幅上限、涨幅宽松带、ST/退市/B股前缀排除、一字板排除 |
| 5 | 候选字段体检 | 剔除关键字段缺失/异常 |
| 6 | 稳健画像 + 避雷 | 涨幅/量比/换手率画像区间、振幅、价格站上均价；风险硬上限 |
| 7 | K 线形态 | 上影线比、收盘接近最高、实体比 → 形态分（⚠ 只有**当日 OHLC**，无 K 线历史） |
| 8 | 深度验证 + 评分 + 分档 | 65 日 K 线深度指标 → 排除规则 → 打分 → 档位判定；末尾 ETF 推荐 |

**涨跌家数（第 3 层的 `涨:平:跌`）口径**：**严格按涨跌额符号** ——
`现价 > 昨收` 记涨、`现价 < 昨收` 记跌、**相等**记平（停牌的最新价就是昨收，故记平）；
现价或昨收 ≤ 0 的行情不参与。`涨跌比 = 涨 ÷ 跌`（跌为 0 时取 999）。
⚠ 不要用 ±0.1% 死区记平（会把平盘虚高一倍多；标准涨跌家数口径按符号）。
⚠ 这不只是显示口径：`涨跌比` 是评分输入（`ratio_ok` → `scoring.bonus.market_ok_ok`），
比值贴近阈值（0.8）时会真实改变分档。详见 `docs/specs/README.md`。

### 3.2 评分体系

总分由三部分构成，全部参数化、可调：

**加分项（12 项）**：均线多头排列（+20）、量能倍数（高/中两档）、连续上涨天数、5 日累计涨幅、
距低点/高点距离、形态满分/通过、大盘环境（好/仅合格）、20 日均线斜率向上。

**扣分项（6 项）**：前一日涨幅过大、偏离均线过远、放量滞涨、长上影、缩量、5 日累计涨幅过低。

**尾盘分时结构（12 项，可开关）**：末 30 分钟量比、尾盘涨幅、收盘位置、尾盘新高、
高点陈旧度惩罚 —— 捕捉"尾盘资金真实进场"的形态。
（这 12 项**在个股详情页有对应的展示卡**，见下面「个股详情 → 尾盘结构」。）

**K 线形态组合（12 个形状，⚠ 出厂默认关闭）**：锤头/上吊线、倒锤头/射击之星、
早晨之星/黄昏之星、曙光初现/乌云盖顶、穿头破脚、身怀六甲、三个白兵、十字星、
蜻蜓/墓碑十字、光头光脚、纺锤、窄幅整理 —— 由 `scoring.patterns` 控制
（看多 +6 / 看空 −6 / 中性 0，单只上限 ±12），**`enabled` 出厂为 `false`**：
形态方向尚未标定，开着就是凭直觉给分。⚠ 关闭时打分那一段一行都不执行（分数与明细逐字复现旧行为）。
（见下面「个股详情 → K 线形态」。）

### 3.3 档位与锁档

| 档位 | 门槛（当前默认版本） | 含义 |
|------|---------------------|------|
| 一档 | ≥ 85 分 | 重点标的 |
| 二档 | 60 ~ 84 分 | 观察标的 |
| 三档 | < 60 分 | 记录但不出信号 |

**均线锁档**：均线未多头排列的标的，分数被压制到 49 分以下（`scoring.tier_lock`），
防止"高分但趋势未确认"的票混进一档。库内同时记录 `score_raw`（压制前原始分）、
`ma_qualified`、`tier_lock_applied`，所以"78 分被锁进三档"与"33 分本来就在三档"可区分。

### 3.4 性能预算

深度验证阶段有耗时预算（默认 120 秒）。超预算时跳过剩余候选并**显式标注**为"未评分"，
不当作"未入选"参与后续信号判定（避免用"引擎没来得及看"否定持续性）。

## 四、三轮对比与信号分类

三轮扫描完成后（15:02），做交并集分析（呈现位置：**「选股结果」时间线的第四格**，2026-10-29 起不再是独立页面）：

| 信号 | 判定 | 含义 |
|------|------|------|
| **最强信号** | 三轮全部入档 | 持续强势 |
| **持续信号** | 多数轮次入档 | 趋势稳定 |
| **脉冲信号** | 仅单轮入档 | 单点异动，需谨慎 |
| **未验证** | 可用轮次不足 | 不输出强弱结论（**不是"弱信号"，是"没结论"**） |

⚠ **「逐标的轨迹」表按上面的顺序排行**（最强 → 持续 → 脉冲 → **未验证最后**）——
强度序是 `SignalType.rank`（唯一来源；`unverified` 排最后，否则"重点股票"里会混进一批没验证的）。

**两道保护**：

- **轮次不足保护**：可用轮次少于应有轮次时一律判"未验证" —— 少一轮无法证明"持续"，
  绝不能把单轮入档升格为最强信号
- **预算截断保护**：被预算跳过、未曾评分的标的，在该轮"缺席"不等于"没入选"，
  一律 unverified 并告警

对比报告同时给出 ETF 推荐（按涨幅/量比在预设 ETF 池中筛选 Top N）。

## 五、四阶段闭环

### 早盘预判（09:30）

根据昨日选股 + 当前大盘灯，为每只标的生成：

- 操作窗口（如 `10:30–11:30`）
- 目标价 / 止损价
- 风险等级与仓位建议（正常仓位 / 半仓 / 轻仓 / 空仓观望）
- 方向描述

五种策略矩阵：`up_consensus`（上午强）/ `up_pulse`（短冲高）/ `down_consensus`（午后修复）/
`down_pulse`（低开反弹）/ `crash`（暴跌日空仓）。红灯日全部转为空仓观望。

### 盘中验证（10:00）

比对预判与实际走势，输出总体/持续/脉冲分组胜率与逐标的明细，并列出**预判偏离清单**。

### 收盘复盘（15:05）

**四层胜率**统计（口径逐层收敛，避免"卖在最高点"的虚高）：

| 层 | 口径 |
|----|------|
| L1 | 次日开盘跳空 |
| 窗口 | 次日 09:30–11:30 窗口内表现 |
| 收盘 | 次日收盘价 |
| **L3 纪律** | 窗口内**首次触及目标价**即视为成交，未触及按窗口末价 —— 最接近实盘可执行 |

同时为**全部已评分标的**（含三档）打次日结果标签写入 `stock_outcomes` ——
这让调优器能在"全部候选"上评估，而不是只在已选中的票里重新排序（消除幸存者偏差）。

#### 多观察窗（T+3 / T+5 收盘）

回答一个上面四个口径都答不了的问题：**「次日午前卖是对的，还是拿三天更对？」**

`stock_outcomes` 除了 T+1 口径，另存两列 **`t3_close_pct` / `t5_close_pct`**
（T+3 / T+5 收盘相对**选股日价格**的涨跌）。历史迭代页的「多观察窗」卡把四个口径并列：

| 口径 | 来源 | 说明 |
|------|------|------|
| 次日午前（主口径） | `disc_profit` | 纪律口径，最接近实盘可执行 |
| 次日收盘 | `close_profit` |
| 持有 3 日 | `t3_close_pct` |
| 持有 5 日 | `t5_close_pct` |

三条要点：

- **T+1 收盘不另开列** —— 就是 `close_profit`（同一列存两遍迟早分叉）。
- **T+3/T+5 由回填补上，不是复盘时算的**：复盘跑在 T+1 15:05，那时 T+3 还要再等
  2 个交易日。所以每次复盘自动把「已到期但还没算」的历史行补掉（只写空值、
  按标的归组取日K、只扫最近 12 个交易日）。**四个口径的样本数天然不同** ——
  看胜率前先看样本数，否则会把「还没到期」读成「拿得更差」。
- **不参与调优标签**：调优标签口径仍是 5 个（Python 时代的 `LABEL_METRICS` 常量已随
  参考实现一起删除，这里保留的是同一份口径），T+3/T+5 只做展示。
  样本集合也与「四层胜率走势」不同（那边来自 `reviews`，只含 T+1 口径），两组数字**不该互相印证**。

### 三天迭代（15:30）

每 3 天汇总：空仓日占比趋势、各层胜率变化、信号类型差异、大盘/分组归因，
输出趋势洞察与仓位建议。空仓占比过高（≥80%）时给出明确警示。

## 六、自选股管理

### 分组与持仓

- 多分组管理（默认组不可重命名/删除）
- ⚠⚠ **默认组（「默认」）= 所有分组的去重总量视图**：
  列表直接展示全部自选、计数取 `watchlist` 全表（一只票一行 ⇒ 天然去重），
  **不数归属表里 `group_id=1` 的行** ⇒ 从默认组「复制到/移动到」别的组，默认组不变少。
  归属表里 `group_id=1` 的行仍在（迁移与 `add` 照常灌），只是界面不再按它过滤。
- ⚠⚠ **一只股票可以同时在多个分组里**（「复制到分组」）：
  归属关系存在 Swift-only 表 `watch_group_members`（`watchlist.code` 是主键，
  一张表存不下多分组）；`watchlist.group_id` 仍同步维护 = 该股归属里**最小**的那个
  （保留它是因**历史行与既有查询**仍按它分组，不能因为新表能表达多分组就把它丢掉）。
- **行右键菜单有两个分组子菜单**：
  - **`复制到分组 ▸`** —— 加到目标分组，**原来的分组保留** ⇒ 同时在多个分组。
  - **`移动到分组 ▸`** —— **组内操作**：从**当前分组**移走 + 加到目标分组，**别的分组保留**。
    （例：某股同时在 A、B 两组，在 A 组里选「移动到 C」⇒ 变成 B、C。）
    ⚠ **默认组例外**：当前分组是默认组时「移动」= 只加不减（等同复制）——
    默认组是总量视图，从它"移走"没有意义。
  - ⚠ 已在的分组在子菜单里**带 ✓ 并置灰**；默认组对每只票都算"已在" ⇒ 恒置灰。
- ⚠ **删分组时**只有"除了这一组再没有别的归属"的票才从自选移除；
  还在别的分组里的只失去这一条归属。
- 每只可标记为持仓并录入成本价、股数 → 自动计算市值与盈亏
  （⚠ 持仓是**按股票**一份，与它属于几个分组无关）。
- 菜单项 **「添加持仓」**——
  行内按钮的悬浮提示与持仓区空态提示**同步用同一个词**（提示里点名的菜单项必须真的存在）。

**金额精度口径**：**成本价 3 位小数、金额与盈亏保留到 0.001 元且不取整**。

| 项 | 格式 | 例 |
|---|---|---|
| 成本价 | **固定 3 位** | `1.249` / `55.879` / `11.000` |
| 成本金额 / 市值 / 盈亏 | **≤3 位、去尾随零、不取整** | `55205.8` / `50291.1` / `+288.9` |
| 盈亏率 | 2 位小数（百分比） | `+0.57%` |
| 回本% | **1 位小数**（百分比） | `+0.6%` |

⚠⚠ **为什么成本价必须是 3 位**：券商**摊薄成本**与 **ETF 净值**本就是 3 位；用 2 位会让
**编辑弹窗预填**被截成 2 位，点一下「保存」就把库里成本价**静默改写成 `1.25`**（市值/盈亏随之全错）。
⇒ 预填走**保真**格式化（`StockFmt.exact`）；⚠ 金额也不用 `%.0f` 取整（3 位成本价 ⇒ 金额可能带 3 位小数）。
详见 `docs/specs/README.md`。

### 自定义提醒（告警）

**提醒只有一个来源：用户在这里手动设置的规则**（引擎的止盈/止损价位仅作参考，不自动提醒）。
**每只标的独立设置**，六类条件（价格 / 当日涨跌额 / 当日涨跌幅，各两个方向）+ 一个提醒时间窗：

| 行 | 条件 | 说明 |
|----|------|------|
| 价格上涨到 | `现价 ≥ 阈值` | 可填多个值，英文逗号（`,`）隔开；**中文逗号与顿号也认** |
| 价格下跌到 | `现价 ≤ 阈值` | 同上 |
| 当日涨额达 | `当日涨跌额 ≥ 阈值 元` | 基准是**昨收**；阈值填**正数**，如 `0.5,1` |
| 当日跌额达 | `当日涨跌额 ≤ -阈值 元` | 阈值同样填**正数** |
| 当日涨幅达 | `涨跌幅 ≥ 阈值%` | 阈值填**正数**，如 `1,3,5` |
| 当日跌幅达 | `涨跌幅 ≤ -阈值%` | 阈值同样填**正数** |
| 提醒时间 | 随时提醒 / 开盘提醒（09:30–10:00）/ 尾盘提醒（14:30–15:00） | 三者**都只在交易日评估** |

- 每个值后面可选「**单次**」或「**每日重复**」——**落库**，不是本次运行内有效：
  单次 = 触发一次后永久哑火（直到重新保存该条）；每日重复 = 每个交易日各一次
  ⚠ 默认值按类型给：**价格类 = 单次**（到一个点位就完了），**涨跌额 / 涨跌幅 = 每日重复**
  （当日累计量的水平线，日内会反复穿越，单次会漏掉后面的穿越）
- 多值即**阶梯提醒**：填 `5,7,9` 会分别在三个档位各响一次（每条独立去重）
- 单条规则最多 10 个值；空着 = 取消该条；**输入非法 → 行内红字报错且不关闭弹窗**
  （不静默丢弃、不静默截断）
- ⚠ **涨额与涨幅是同一个数的两种刻度，不是两份独立证据**：一只 10 元的票涨 1 元 = 涨 10%，
  一只 1000 元的票涨 1 元 = 涨 0.1%。同一只票两个都设、若刚好对上，会在**同一刻各响一条**
  （通知标题不同：「涨额提醒」/「涨幅提醒」）。弹窗里有这行提示
- 涨跌额取的是**自选表「涨跌额」列显示的那个数**（接口原值）—— 判据与界面**同源**，
  不会出现"界面显示 +1.00、提醒却按别的数判"
- **提醒只来自这里手动设置的规则**：引擎从判定结论算出的目标价 / 止损价（`watch_judgments`）
  只在弹窗里作为**只读参考**显示、可一键填入，**不会自动弹通知**（0.6.10 起；
  此前会自动提醒，导致自选里每只持仓票都可能收到没设过的止损/止盈通知）
- ⚠ **告警是常驻评估的**：行情由 `AlertMonitor` 一个轮询方供数，自选页与告警**共用同一批**行情。
- 设置页「**提醒**」卡：通知授权状态（未授权时提醒会静默不响）+「暂停全部提醒」总闸
  ⚠ 「**发一条测试**」按钮：授权状态只说明"系统允许了"，**不代表链路真的正常**
  （实测反例：通知左侧应用图标缺失，而图标文件本身完全正常）⇒ 给一键自检入口。
  + 全部已配置提醒一览（可直接编辑）

## 七、次日区间估计

对任意标的（自选页 / 个股详情）可拉取**次日高低点统计区间**：

- 方法：以"每日高低点相对前收的偏离"做分布取分位数 → 用近期振幅算波动倍数 k（钳在 0.6~2.0）
  → 区间 = 前收 × (1 + 分位数 × k)
- 自带**逐日滚动回测（walk-forward）**：预测第 t 日只用 t 之前的数据，统计命中率
  （**没有未来函数**；偏乐观的来源是模型参数取自同一段历史 + 测试窗口只覆盖最近样本）
- 输出一律是**区间 + 历史命中率 + 误差量级**，并附三条 caveat（回测偏乐观、
  大盘剧烈波动/一字板时失效等）

> 定位：这是**统计区间估计**，不是确定性预测，也不构成买卖建议。

- **出厂版本**（5 个）—— ⚠ **版本名与文件名不同构**，映射只能查随包元数据

  | `默认` | `classic_2026_7_16.json` | 经典基线；**受保护不可删**（`protected_versions`） |
  | `backtest` | `backtest_v1_1_0.json` | **已被取代**（见下） |
  | `backtest-1.2.0` | `backtest_v1_2_0.json` | **已被取代** |
  | `backtest-1.3.0` | `backtest_v1_3_0.json` | **当前默认**（`default_active`） |

  ⚠ **`superseded_defaults`**：`backtest` 与 `backtest-1.2.0` 已被 `backtest-1.3.0` **取代** —— 老机器的

- **用户版本**：从任一版本复制/编辑后另存为新版本

- ⚠ **出厂行落库后即用户数据**：启动补种**只补缺失的行、永不覆盖已有行**。
  出厂参数/描述的**唯一覆盖入口**是版本卡底部的
  「恢复出厂设置」按钮：用随包文件覆盖一次出厂行（参数 + 描述），缺失行重新插入并**清墓碑**，
  自定义版本不受影响（`ParamStore.restoreBuiltins()`）
- **描述可编辑**：版本行点描述文字弹 popover 修改，落库 `param_versions.note`
  （出厂/用户版本一视同仁；恢复出厂会把出厂行的描述还原为随包 `note`）

### 编辑体验：13 个 `json` 参数用**结构化控件**，不再是裸 JSON 文本框

按**形状**分三类渲染（`ParamTableSpecs` 声明，`ParamTableEditors` 实现）：

| 形状 | 参数 | 控件 |
|------|------|------|
| **阈值→分值表**（6） | 连涨 / 5日累计 / 距低点 / 距高点加分表、前日涨幅 / 乖离率扣分表 | 每档一行：比较符下拉 + 阈值 + 分值，可增删档位 |
| **参数化判据**（4） | 滞涨 / 长上影 / 缩量 / 5日累计过低扣分 | 命名行（中文标签 + 数值），`5日累计过低` 另有「停用本项」开关（= 显式 `null`） |
| **复合配置**（3） | 预判策略表（5 策略 × 6 字段）、迭代阈值表（12 项）、**大盘状态门槛浮动**（5 态 × 3 调整量） | 逐策略分块（窗口/目标/止损/风险/仓位/提示），风险与仓位走下拉；门槛浮动是 5 行 × 3 列（目标价/止损价/打分线） |

几条关键设计：

- **键名由 `(比较符, 阈值)` 拼出**（`Screener.thresholdKey`，与解码的 `keyThreshold` 紧邻放置，
  编解码同源）。所以"改阈值"就是"改键名"。
- **必填档位阈值只读 + 不可删**（行尾 🔒）：`REQUIRED_JSON_KEYS` 固化的是默认值的键名，
  改了会让参数校验报「缺少子键」而保存被拒。**新增**的档位没有这个约束。
- **提交时机是回车 / 失焦**，不逐键提交 —— 改阈值会改键名，逐键提交会让行身份在
  输入过程中反复变化（视图重建 / 焦点丢失）。
- **键名冲突拒绝并提示**，不静默覆盖（两个档位合并成一个，用户不会察觉）。
- 行编辑逻辑抽在 `SelectedCore/ParamThresholdTableOps.swift`（纯函数），视图只负责画（UI 层只过 `swift build`，抽出来才能被 `swift test` 覆盖）。
- **覆盖性护栏**：`ParamTableSpecsTests` 断言 specs 的键集合**恰好等于** schema 里 `type == "json"` 的键集合
  （新增 json 参数忘了配 specs 会**测试红**，而不是悄悄退回裸文本框）。渲染处的 `switch` 也**故意穷尽**（不带 `default:`）。

### 校验与告警

- **类型/范围校验**：数值上下限、区间倒挂、列表长度、嵌套必填子键
- **跨参数一致性**（都是**错误**，会阻断保存）：
  - 二档门槛必须低于一档门槛；锁档上限必须低于一档门槛
  - **逐层收窄**：硬过滤涨幅带 ⊇ 画像涨幅区间；涨幅带下限 ≥ 跌幅下限；
    画像区间上限 ≤ 对应的硬上限（量比 / 换手率 / 振幅）
  - 红灯连跌天数至少为 1

> 「逐层收窄」防**静默截断**：内层调宽被外层卡住而界面无提示。
> 这五条一致性都是**错误**（阻断保存），不是告警。

### 参数调优

入口在参数中心左域导航的「参数调优」域。**全局参数是唯一口径** —— 没有个股级覆盖与单股调优。

对历史已入档标的做**反事实重放**：用候选参数重算档位，与真实次日表现比对。

- 目标口径可选：L3 纪律（默认）/ L1 跳空 / 窗口 / 收盘 / 理论最高
- 随机搜索 + 爬山精调（同 seed 同结果，可复现）
- 输出 Top 5 候选 + 与基线的逐标的回测对比（改善/变差/持平）
- **结果仅作参考，不自动应用** —— 需人工确认后存为新版本
- **评估池窗口**：`iterate.tune_pool_days`（默认 120 个交易日）限定只取最近 N 天。
  调优耗时 ≈ `候选数 × 池大小`（UI 走全默认 `trials=200`），不加窗口会**随使用年限线性增长**；加窗口后耗时封顶。
  结果里会给出 `pool_days`（配置窗口）/ `pool_dates`（实际天数）/ `pool_window`（日期区间），
  面板上显示为「样本跨度：N 个交易日（起 ~ 止）」—— **样本量直接决定结论可信度**

  > ⚠ 这个键**刻意不在参数中心**（属引擎侧只读开关，与 `phases` 同类）：`validate` 对"**键缺失**"会报错，
  > 声明成 schema 项会让**所有存量参数版本**校验失败、连带 `params save` 被拒
  > （`cum_5d_low` 踩过同一个坑）。要暴露到参数中心需连同"给全部存量版本补键"的迁移一起做。

- **样本门槛**：样本不足时**不出结论** —— 结果里给出结构化的 `sample_gate`
  （`sufficient` / `samples` / `threshold`，默认门槛 30 只），界面据此把候选列表换成「样本不足，不出结论」。
  没有判据的旧结果按"不足"处理但不显示提示（不擅自给老结果加告警）
- **覆盖缺口**：`counterfactual` 报出同窗口内被淘汰（未并入评估池）的样本条数、
  其中带可重评分特征的条数、以及缺哪些列。被淘汰样本的行情/深度特征**从未落库**
  （`excluded_stocks` 只有 `code`/`name`/`reason`）→ 当前恒为 0 条可并入；判据取自表结构实际列名，
  补上列后会自动变成真实计数
- **参数时代**：`param_eras` 报出评估池里每条样本**按 `sel_date` 反查到的当日生效参数版本**
  及其样本数，跨多个版本时给告警（用 A 时代入档的样本去优化 B 时代的参数）。**不做"按当日版本分别评估"**
  （会让不同样本跑在不同基线下、指标不可比）。版本生效日期存在 `param_versions.effective_from`
  （Swift 独有列，见决策台账 `docs/specs/README.md`「独有数据库列」）

### 历史回放（收盘价口径）

回答两个问题：① 调优样本能不能扩到**几年**？② 引入新评分项前，能不能先在历史上验证它有效？

入口在**设置页 → 历史回放**。三步：下载日K缓存 → 选区间 → 开始回放。

#### ⚠⚠ 先说清楚：这是「收盘价回测」，不是「尾盘重放」

| 维度 | 实盘 | 历史回放 |
|------|------|---------|
| 选股价 | 14:00 / 14:30 / 14:50 的**盘中价** | **收盘价** |
| 量比 | **盘中时点**量比 | **全日**量比 |
| 尾盘分时结构（12 项） | 参与评分 | **整块跳过** |
| 股票池 | 当时的在市清单 | **当前**清单（退市票缺失） |

原因是**物理限制，不是实现缺陷**：分时数据不可回溯（新浪 5 分钟线只覆盖最近约 5 个交易日）。
→ **回放样本与实盘样本口径不同，不可直接比较**。所以：

- 回放写进库的复盘会打上 `reviews.scan_mode = 'replay_close'`（实盘是 `'live'`）
- **调优池默认只用实盘样本**（`PhaseTune.buildPool` 的 `scan_mode='live'`）
- 要用回放样本，在参数中心的调优面板上勾「纳入历史回放样本」—— 勾上后调优结果里会明确标注
  「已含历史回放样本（收盘价口径）」，避免"池突然变大"无从解释

#### 下载缓存（可取消、可续传）

- 数据源是**东财日K**（`push2his.eastmoney.com`）。新浪日K只有 OHLCV，缺**成交额 /
  换手率 / 振幅**，而硬过滤要吃这三项 —— 不够用
- 一次请求给约 **1145 根（4.6 年）**，且按**日期区间**取
- 首次全市场约 **5000 次请求 / 10–20 分钟**。`bar_coverage` 记每只票**请求过的窗口**，
  中途断网/退出/取消后**再点一次接着下**，已下载的不重下
- 缓存落在**独立库** `history.sqlite3`（与主库同目录）：约 300–400 MB，纯缓存，可随时清空重下。
  不塞进主库是因为它会让备份/导入/迁移都变重
- ⚠ 返回 0 根的票**不记**覆盖记录（下次会重试）：数据源分不清"网络失败"与"这只票真没数据"，
  一律记账会让一次网络抖动把一批票**永久**排除在缓存外

#### 回放（隔离规则）

- 逐日重建**全市场快照** → 跑一轮扫描（slot 3）→ 跑预判 + 复盘（含 `stock_outcomes` 标签）
- **只写库里还没有该日数据的日期**：该日已有任何扫描轮次 → **整日跳过**（live 数据永不被回放改写）
- 回放期间**调度器与手动扫描/阶段重算一律被拒绝**：回放是进程级开关，
  此刻跑实时任务会把重建出来的历史行情当成今天写进库
- 回放日的 `slot_label` 写的是「收盘(回放)」而**不是** 14:50 —— 不冒充真实的尾盘轮次

#### 已知不足（有意接受）

1. **不是尾盘口径**（见上表）—— 物理限制
2. **股票池用当前清单** → 早年回放的候选池**偏小**，幸存者偏差方向是"高估策略收益"。
   缓解：回放日的 `total_scanned` 会明显小于实盘，结果行里直接可见
3. **量比口径不同**（全日 vs 盘中时点）→ 量比相关的过滤与打分在回放日系统性偏移
4. **外盘数据不参与**（无历史端点）→ 回放日的大盘环境缺海外分项
5. **回放不做 3 轮**（只 1 轮收盘价）→「三轮持续信号」类判定在回放日**不成立**

设计论证见 `docs/specs/README.md`。

  （`push2his…/fflow/daykline/get`）**单独在册**（`eastmoneyFundFlow`），
  **永不写进 `stock_fund_flows`**；`swift test` 里有反合并用例钉它。
  另注：东财把全市场看成零和（小单+中单+主力 ≈ 0），它**没有**「总净流入」这个概念。

  `data_source_logs`（`round_budget_exceeded` / `round_aborted`）
- **K 线缓存**：日K/指数K 按 `(标的, datalen, 当日)` 缓存（新浪盘中不含当日 bar，日内恒定）；
  5 分钟线 60s TTL；**fixture 模式不缓存**、**只缓存非空结果**。
  限速（`klineDelay`）只在**真的走网络**时生效 —— 缓存命中不再白付节流税
- **数据源自检**：设置页可手动触发，启动后自动首检、每小时复检，逐渠道显示状态灯
- **启动期库维护**：`wal_checkpoint(TRUNCATE)`（回收 WAL）+ `PRAGMA optimize` +
  `data_source_logs` 保留 30 天
- 所有数据源事件（刷新/回落/失败）落库 `data_source_logs` 可追溯

⚠ **选股结果页的明细表：列宽按内容实测，富余只进「相等的列间隙」**（2026-10-26 老板两次打回后的口径）：
最小窗口 1120 − 侧栏 144 − 页面 padding 18×2 − 卡片 padding 14×2 = **912pt 可用**（这枚宽度从 `FitScrollView`
实测，**不许量卡片或表头** —— 行是定宽 HStack，量它会在窗口缩小时把卡片反向撑宽，永远回不去）。
指标列宽 = 该列最长内容（表头与所有单元格取大者，`NSString.size` 实测）× 1.35 + 4，名称列同规则（下限 110、上限 170）；
固定列 = 分数 66 + 三轮分 88 + 尾部 32；剩余宽度先拉匀 8 段间隙（每段 6→32pt 封顶），封顶后才按内容比例回摊。
**每列内容与表头都居中**（右对齐会让短数字贴着列右边界，与表头之间出现空洞）。
⚠ 两个方向都不许走偏：① 不许 `maxWidth:.infinity` 把剩余**均分**给 5 列 —— 4 字的「量比」与 7 字的「成交额」
一样宽，列内全是空白、最后一列还跟三轮分贴上（老板第一版打回的就是它）；② 也不许把富余全塞进列内（列宽 ×2）——
空白只是换个地方继续存在。
⚠ 行本体必须 `.frame(maxWidth:.infinity, alignment:.leading)` 钉左：不钉的话行宽小于卡宽时整行会被**居中**，
分数列与表头错开半张卡（实测窄窗口偏 230pt）。
**改任何一列都必须重算这条**。列宽常量收在 `ResultsTableMetrics`（分数/三轮分/尾部/间隙下限），
表头 `pickHeader` 与数据行 `pickRowTail` 共用同一个 `PickTableLayout` 实例 —— 之前是两边各手写一遍数字，
改一处忘另一处就错位。

**表格行分隔只有一条 hairline，没有斑马纹**（护栏 `no_zebra`）：隔行上色与 `zebra` 开关整族拆除 ——
老板 2026-10-23 判「斑马条纹表格很丑」，方案表里选了"只删交替纹、自选那层整行底留着"。
`SharedDataTable` 连开关都不留：留着开关 = 下一个人顺手就打开。

**对齐口径：表头与数据行的 alignment 只能从同一处取**，调用点自己写 `.center` 就是错位之源。

**自选 / 持仓表头排序**：点表头 **升 → 降 → 取消**（取消 = 回到库里的加入顺序），

⇒ 新增列不表态就编译不过）。⚠ **判定列有意不可排**：动作词是分类量不是有序量
（`Sem.actionColor` 把"买入"与"止盈卖出"归成同一支红，这套词里没有自洽的强弱轴），

**同值必须稳定**（自选页每 5s 轮询，不稳定就会自己跳行）、
**排序值与显示值同一个算式**（持仓派生量收口成 Core 的 `HoldingMetrics`，视图不再自己写一遍）。

  ⚠ 标题**只在开窗时钉**（首次 + 200ms 各一次），此后永不写 `window.title` —— 写标题会触发标题栏重排，
  AppKit 顺势把红绿灯摆回 12/13.5，肉眼就是「点标签切分类时跳一下」（0.5.99 实机复现）。主窗口从不写标题，所以不跳。
  红绿灯 (18,18) 与主窗口**同一套现成实现**：探针装 `.unifiedCompact` 空工具栏带 + `.toolbarBackground(.hidden)` 把带压透明，
  再手摆按钮到「左 / 上 18」。⚠ `didUpdate`/`didResize` 观察器**只发现、只排队**，实际移动在下一轮 runloop；
  **绝不在布局回合里同步摆** —— AppKit 在同一轮末尾会把按钮摆回 12/13.5，同步摆会变成"摆到 18 又被摆回"，
  每次重绘抖一次（0.5.98 实机看到红绿灯持续跳动）。设置窗口**没有**切页补摆、标题自愈这类专属机械。
  ⚠ **开窗不跳**：两个窗口首次挂载时三颗灯先 `alphaValue = 0`；等窗口上屏、首轮布局与标题补钉都过去（300ms）
  再启动 0.1s 淡入，**并在同一轮 runloop 立刻补摆一次**（`hideThenRevealOpeningTrafficLights`，主窗口与设置窗口共用）。
  ⚠ **顺序不能反**：`alphaValue` 0→1 本身会同步触发 AppKit 的标题栏重排（把按钮摆回 12/13.5），
  所以必须「先淡入、紧跟着同轮摆位」—— 两者都发生在下一次绘制之前，肉眼看不到中间态；
  先摆后淡入 = 复位把摆位顶掉、下一轮再补摆，就是「刚打开跳一次」（0.5.101 实机复现）。
  左侧分类列**首行 pill 绝对顶 = 40**（safe area 下 10；让开红绿灯；图标左缘与红绿灯圆点同落 18pt 线）；右侧内容从约 24pt 开始，
  分组标题高于侧栏首行 —— 与 MiscKit 设置页同一套几何（不要求两列首行文字齐平）。
- ⚠ **窗口尺寸被 AppKit 自动记忆**（`UserDefaults` 的 `NSWindow Frame com_apple_SwiftUI_Settings_window`）
  ⇒ 改默认尺寸时**必须一次性清掉旧记忆**，否则新默认永远不生效
  （`AppDelegate.resetSettingsWindowFrameOnce()`；只清一次，之后用户自己调过的尺寸照常记忆）。
- ⚠ 分类图标是**单色 SF Symbol**（与主窗口侧栏同一套语言）：本项目里颜色是**数据语义**
  （涨跌红绿 / 灯级 / 信号 / 风险），分类图标不是数据，不上色 ——
  否则"红色"会同时意味着"上涨"和"某个分类"，正是本项目一直在消除的歧义。
  ⚠⚠ **图标名必须真实存在**：写错时 SwiftUI **什么都不画**（不报错、不占位）⇒
  新增自检 `symbol_names` 把源码里的图标名逐个拿去问 AppKit（`NSImage(systemSymbolName:)`）—— 名字不存在时画不出任何东西，肉眼与编译都发现不了。
- ⚠ 分页还有一层**性能**收益：`Card` 的 content 闭包是**饿求值**，分页后一次只构造 1~3 张卡
  （否则每次状态变化都要付全部构造开销）。
- **字号与间距档位**：
  字号全走语义档。**macOS 26 的真实磅值用 `NSFont.preferredFont(forTextStyle:)` 量**
  （SwiftUI 的 `.caption` 对应 AppKit 的 `caption1`，**别按 iOS 文档的表对号**）：
  页名 `.title3.bold()`（**15**）＞ 卡片标题 `.headline`（**13**，`Card` 统一提供，且自带 Bold 字重）
  ＞ 行标签 `.callout(.bold)`（**12**）＞ 正文/次要 `.caption`（**10**）＝ 可选提示 `.caption2`（**10**）；
  另外两条实测结论与直觉相反，改文档时别再写回去：
  ① **`.caption2` 不比 `.caption` 小**，两者都是 10pt，差别只在 `.caption2` 默认是 **Medium 字重**
  —— 所以"注脚两档"实际是**一档字号 + 两种字重/颜色**，不是两个字号；
  ② `.headline` 与 `.callout` 只差 1pt（13 vs 12），卡片标题的层级感主要靠**字重**（headline 自带 Bold）
  而不是字号，别指望调字号能拉开它们。
  **无一处硬编码 pt**（`AppFont` 那套 9/10/11/12pt 只给详情页密集网格）。
  **注脚只许两档**：需要看的信息（口径说明/时间/数量/行动指引）= `.caption`+`.secondary`；
  可选提示（占位「尚未…」、「…其余 N 只」）= `.caption2`+`.tertiary`。
  ⚠ 两档的**可读性差异只来自颜色**（`.secondary` vs `.tertiary`），字号相同 ——
  高对比度外观下系统会自行增强，但"淡一档"这件事在浅底上本来就只剩 3 级灰。
  间距：卡片之间 14 / 页内边距 16（与主窗口各页一致）、**卡内首层 14（hero 18 / subtle 12）**。
  ⚠ 卡片标题已移到卡外做分组标题（11pt 次级），卡面只包内容 —— 一处改全站统一。
  ⚠ **macOS 不支持 Dynamic Type**（HIG Typography 原文），所以"字太小"在 Mac 上唯一的合规出路
  是应用内自建密度档位，不是接系统文本缩放。

**异动提示**（**只在命中时出现**，不占位）：涨跌停 / 一字板 / 放量大跌。

⚠ **判据是「该板块」的涨跌停价，不是固定 10%** —— 腾讯直接给了每只票自己的涨停价/跌停价，
而档位是**板块相关**的。实测「涨停价 ÷ 昨收」：

| 板块 | 实测 | 说明 |
|------|------|------|
| 沪 / 深主板 | **1.100** | ±10% |
| 创业板 · 科创板 | **1.200** | ±20% |
| **北交所** | **1.300** | ⚠ **±30%，常识里没有这一档** |
| ST（主板） | **1.099~1.101** | ⚠⚠ **实测是 ±10%，不是旧常识里的 ±5%** |

所以任何"硬编码档位表"都会写错 —— 直接比腾讯给的价才是唯一正确且免维护的判据。
（另外：**指数**的这两个字段是 `-1` 哨兵值，不判 `>0` 会把每条指数都判成"涨停"。）

- **一字板**：开 = 收 = 高 = 低 **且**停在某一侧的板上（只有"四价相等"不算 —— 那可能是全天停牌）
- **放量大跌**：跌幅 ≤ -9.5% 且成交额 ≥ 2 亿且量能倍数 ≥ 4 倍（量能倍数复用引擎同款公式）
  ⚠ 口径边界：-9.5% 是**主板跌停的位置**，对 20%/30% 的板块偏低（创业板 -19% 不会命中）。
  这是清单原文的口径，**有意保留** —— 换成"该板块跌停幅度的一半"会让同一张卡在不同板块表达不同意思

**策略命中**：详情页列出 InStock 模块 7 那**六条独立选股策略**的命中情况

**超买超卖**：详情页一组**六条固定阈值信号** ——
**KDJ / RSI / CCI / CR / WR / VR**（清单模块 4），每条给出**读数 + 档位 + 阈值依据**
（如 `KDJ 超买｜K 85.20 · D 72.10 · J 111.40`）。**零新数据源、零额外请求**（纯日K计算）。
⚠⚠ **只展示 —— 不进评分、不进筛选**：清单写明这类固定阈值信号与评分体系是**两套哲学**、不建议引入，
且 `CorrelationDiagnostic` 已量到 KD / RSI / MACD 同源高度相关（把相关读数当独立证据会**高估可信度**）。
⚠⚠ **这六条不是六份独立证据**：KDJ / WR / CR 都基于「价在 N 日高低之间的位置」、
CCI 用均值偏离、只有 VR 用量能，而 **MFI（已有）与 RSI 同族** → 真正提供
"不同信息"的可能只有 **2~3 条**（这一点写在卡片上）。
⚠⚠ **阈值是清单给的、公式是"我们的读法"**（清单只写了判据、没写公式）：
KDJ 初值 `K=D=50`、**一字板 `H==L` 时 RSV 取中性 50**（取 0 会读成"极度超卖"、
取 100 读成"极度超买"，都是在**没有位置信息**的地方硬造结论）、RSI 用**简单平均**
（不是 Wilder 平滑）、CR 的中价取 `(H+L)/2`、VR 的平盘 = **收 == 昨收**。
⚠ **VR 是唯一的区间型判据**（`160–450` 获利了结 / `40–70` 买进），
**区间之外是中性**，不是"反向信号"。
⚠ **"未评估"与"中性"分开显示**：日K不足 / `MD==0`（无波动）/ 分母为 0 时那条判据**根本没跑**，
会单列一组并写明原因（如"区间内无波动（MD=0）→ 算不出 CCI（**不是**中性）"）。详见 `docs/specs/README.md`。

**基本面**：详情页一组**五组基本面** —— 估值指标（动态/TTM/静态 PE + PB）/

⚠⚠ **刷新失败时会把 HTTP 层的真原因写出来**：如
`未刷新（保留旧数据）：抓取失败：The network connection was lost.` —— 不把**被限流**与**没网**混成一件事。
⇒ **三处批量抓取一律走全局限速器**（护栏 `push2_throttled`）+ **每页失败秒级退避重试**；
但若源**返回被截断**（实得 < 源报总数），整轮判为不完整并**丢弃**（宁可不刷也不用半份数据）。
⚠ 遇到刷新失败**先看那句原因**：`The network connection was lost.` = **出口 IP 被限流**，
换代理节点 / 设为直连后重试即可（本项目不做绕过用户代理的代码）。
⚠ **数量下界护栏**：全市场 < 4000 只 → 不写库、保留旧数据（源对"抓取失败"与"真的没有"
都返回空，拿空表覆盖会让详情页卡片**静默消失**）。
⚠⚠ **只展示 —— 不进评分、不进筛选**：清单定性它是「**慢变量**，与"次日午前"尺度不匹配」（模块 1.2 里
`每股指标/成长能力/偿债能力` 都标 **✗**），本项目取向也是"选股不掺基本面"。
⚠⚠ **清单的六组里只做了五组**：第六组「**股本股东**」要的字段**算术上校验不过**
（东财 `f` 编号含义各家文档不同，本实现逐个用**算术恒等式**在真实响应上验，验不过的**一律不用**）→ **宁缺勿错**。
⚠⚠ **「—」= 源没给，不是 0**：源用 `-` 表示"没有"，若折成 0 会显示成「**资产负债率 0%**」（= 无负债），
与"没数据"**完全不同的结论** → 解析 / 落库（NULL）/ 读取 / 分组**四层都不折**。
⚠ 「刷新了 N 只」与「其中 N 只有数据」是**两件事** —— 退市 / 停牌票会返回全 `-`，所以设置页两个数都显示。
详见 `docs/specs/README.md`。

**筹码分布**（仅日K时显示）：回答「**上方套牢盘重不重**」（比"距高点多远"更贴近

**K 线形态**（仅日K时显示）：回答「**图上最后一根 K 线是哪种已知形态**」——
识别 12 个**当日 / 两日 / 三日**的短周期形态并逐个列出（中文名 + 方向徽章 + 用了几个根K线 + 命中依据）：

| 形状 | 前序下跌 → | 前序上涨 → |
|------|-----------|-----------|
| 长下影小实体 | **锤头**（看多） | **上吊线**（看空） |
| 长上影小实体 | **倒锤头**（看多） | **射击之星**（看空） |
| 三根反转 | **早晨之星**（看多） | **黄昏之星**（看空） |
| 两日贯穿 | **曙光初现**（看多） | **乌云盖顶**（看空） |
| 长影十字 | **蜻蜓十字**（看多） | **墓碑十字**（看空） |

另有 7 个**不依赖趋势语境**的形状：穿头破脚（阳包阴/阴包阳）、身怀六甲（孕线）、
三个白兵、十字星、光头光脚、纺锤、窄幅整理。

⚠ **形状 ≠ 名字**：锤头与上吊线的 K 线形状**完全相同**，只有"出现在下跌后还是上涨后"
这一条区别 —— 这是形态学本身的定义。**趋势走平时语境形态不出**（硬按一个方向命名等于编造信号）。
⚠ 12 个形状**互斥**（每条判据都带互斥条件），不会把同一个 K 线组合报成三个形态。

**量能 · 连续**（同一张卡的第二组）：与 12 个**形状**是**两类判据**，故**分开展示**
（形状是**互斥分类**，量能/连续性与它**正交**）。

| 判据 | 口径 | 出厂阈值 |
|------|------|---------|
| **天量** | 今日量 ÷ 前 5 日均量（**不含当日**） | ≥ **3.0×** |
| **连涨放量** | 连涨 ≥ N 天 **且** 今日量 ≥ 前 5 日均量 × K | N = **2**、K = **2.0×** |
| **下跌无量** | 今日跌 **且** 今日量 ≤ 前 5 日均量 × K | K = **0.7×** |
| **连续阳线 / 阴线** | 连续 `收 > 开`（或 `收 < 开`）≥ N 根 | N = **4** |

- ⚠ **这几条阈值是本项目的出厂默认值** —— 清单点名了这几条判据但**没给数**
  （它只给了"放量跌停"那一条的量能倍数，那条落在「异动提示」里）。可调，**改动等于改口径**。
- ⚠ **「连阳/连阴」与引擎的 `consec_up`（连涨天数）不是一回事**：前者按**阳线**（`收 > 开`），
  后者按**涨幅**（`(今收-昨收)/昨收 > 0`）。**跳空高开但收阴**的票计入连涨、**不**计入连阳。
- ⚠ 天量与下跌无量的方向是**中性** —— 天量上涨与天量下跌是两回事（方向写在依据里）；
  "缩量下跌"多被读作抛压衰竭，那是一种**解读**而不是方向信号（与十字星/窄幅整理同处理）。
- 连阳/连阴用清单里的传统名：**四串阳**（4）/ **八仙过海**（8）/ **九阳神功**（9）/
  **七仙女下凡**（7 连阴），其余按 `N连阳` / `N连阴`；依据里始终带**数字**。
- ⚠ **不做「旭日东升」**：它与「穿头破脚（阳包阴）」是**同一形态的两种叫法**，加进去会破坏"12 个形状互斥"。
- ⚠ **只展示、不参与评分**（与 12 个形状同一理由：方向尚未标定）。

**技术指标**（仅日K时显示）：ATR / OBV / MFI / BIAS 四个。
（清单用 talib 算 32 个、明确不建议全量移植：架构硬约束 + 其口径是特调的。详见 `docs/specs/README.md`。）

| 指标 | 口径 | 展示形式 |
|------|------|---------|
| **ATR(14)** | **Wilder 平滑**（不是 TR 的简单均值）；`TR = max(高−低, \|高−昨收\|, \|低−昨收\|)` | 绝对值 + **占价 %**（跨股票可比） |
| **OBV** | `收>昨收 → +量`；`< → −量`；`= → 不变` | **20 日变化量**（带符号） |
| **MFI(14)** | 典型价 `(H+L+C)/3` 的带量 RSI | 数值（0–100） |
| **BIAS(6/12/24)** | `(收盘 − MA_n) / MA_n × 100` | 三个周期的百分比 |

⚠⚠ **四处"看起来等价其实不同"**（都写在卡上的口径行里，因为都是会让人误判的点）：

1. **ATR ≠ 振幅**：振幅只看**当日区间**（`(高−低)/昨收`），ATR 的真实波幅含**跳空**
   （`|高−昨收|` / `|低−昨收|`）→ **跳空日两者会明显分叉**。
   这正是清单说 ATR"与次日高低点区间天然互补"的意思 —— 那张卡用的是振幅。
2. **OBV 的绝对值没有意义**：它取决于**从哪一天开始累计**（不是价格水平）→ 卡上只给变化量。
3. **BIAS ≠ 加减分明细里的「偏离均线」**：那个是 `|MA5−MA10|/MA10`（量的是**均线之间**），
   BIAS 是 `(收盘−MA_n)/MA_n`（量的是**收盘对均线**）。名字都带"乖离"，不是同一个量。
4. **MFI 的 80/20 是传统参考线，不是本项目的判据** —— 固定阈值买卖信号已被明确否决
   （它与评分体系是两套哲学）。

⚠ **四项均不参与评分**（方向尚未标定）。**零新增数据源**：用**图上已加载的日K现算**（与筹码分布同款，不发请求）。
⚠ 实测腾讯 `newfqkline` **已经包含当日 bar**（开盘前就带当日日期）→ 不需要拿实时行情合成一根，
少一处口径不一致的机会。⚠ 尾部"尚未形成"的占位 bar（`high/low` 全 0）会被剔除 ——
不剔的话 12 个形态会全落在一条假 K 线上，而且**不报错**。
⚠ **打分出厂默认关闭**（`scoring.patterns.enabled = false`）—— 见 §3.2「K 线形态组合」。设计论证见 `docs/specs/README.md`。

**尾盘结构**：回答「**最后半小时到底是抢筹还是出逃**」——
配四个数字：尾盘量能（末 30 分钟量比）、尾盘涨幅、收盘位置（当日最低=0 / 最高=1）、
尾盘量占比，再标出尾盘是否创新高、日内高点时刻、高点距今比例。
⚠ 这与上面几张卡**性质不同**：**尾盘分时结构本来就是评分输入**（12 项，可开关，见
「评分加分项/扣分项」一节的 `尾盘放量倍数下限` / `尾盘放量加分`），这张卡只是把
**已经在算的那个结果**显示出来 —— 故卡片上**不写**"只展示、不参与评分"，
反而要写明它**用的是哪一档参数**（尾盘窗口 30 分钟、最少 bar 数），
且**复用评分用的同一个纯函数**（`IntradayFeaturesCalc.compute`），避免界面口径与评分口径悄悄分叉。

数据来源与节奏：**零新增数据源**，按需取一次腾讯 5 分钟线（一次 240 根 ≈ 5 个完整交易日 + 今天，
走既有的 60s 内存缓存）。⚠ **选日逻辑是"最近一个 bar 数够算的交易日"**而非"最新一天"（盘中 10 点今天只有 6 根 bar）。
⚠ **选中日与行情快照必须同一天**：选中日 = 今天用实时行情、是历史日则**用那天的最后一根 bar 重建** ——
混用（今天的价 + 那天的最高最低）会让"收盘位置"算出大于 1 的值，且**不会报错**。设计论证见 `docs/specs/README.md`。

**回撤风险**（仅日K时显示）：回答「**这只票有没有暴跌过、涨太多没**」。
展示近 **60 个交易日**的**累计涨幅**与**最大单日跌幅**，并给出是否满足「无大幅回撤」的判定。

口径（来自清单 §模块 7 #6）：**无大幅回撤** = 累计涨幅 ≤ **60%** **且** 无单日跌超 **7%**。
全程**收盘对收盘**（与评分里的「5 日累计涨幅」同口径）。
⚠ `60日涨幅<0.6` 里的 `0.6` 读作 **60%**（InStock 配置里比值都写小数，如"量比≥2"= 2 倍）
—— 这是**读数**不是既定事实，所以阈值可调。

⚠⚠ **与「距高点」不是同一个量**：那个量**下跌侧**（现价距 60 日最高收盘，防接刀），
这张量**上涨侧**（首收→末收的累计涨幅，防追高）。一只"就在最高点"的票在那边看起来
毫无风险，在这边可能已经涨了 300%（有单测构造了这个用例）。
⚠ 与既有三层风险结构**逐条核过**：第 3 层的 -7% 是**当日**跌幅、第 6 层是量能口径、
第 8 层的深度趋势排除量**下跌侧**、`cum_5d` 是 **5 日** —— 实测引擎里**没有**"60 日累计涨幅"、
**没有**"区间最大单日跌幅" → **两条都是新维度**。

⚠ **本卡不参与筛选**（有意）：做成排除项只能"新参数 + 默认关"，而"默认关的旋钮"正是本项目
反复踩过的坑；且**方向尚未标定**，而核心策略是**动量型**，"防追高"与它有张力。详见 `docs/specs/README.md`。

**早盘抢筹**：回答「**今天早盘资金进得猛不猛**」。
配四个数字：**早盘量比**、早盘量占当日比、早盘涨幅、早盘是否创当日新高。
默认窗口 **09:30~10:00**（与「盘中验证」的 10:00 时点对齐）。

⚠⚠ **口径与「尾盘结构」不同，这不是同一张卡的两个数**：
尾盘那张的基准是「**当日已交易平均**」，那套口径在早盘**不成立** ——
10:00 时窗口就是全天已交易时段，比值**恒等于 1**。
所以早盘用**跨日同窗口对比**：`今日早盘量 ÷ 前 N 个交易日同时段均量`，
天然不受「A股成交量呈 U 形分布」（早盘、尾盘量大）影响。
⚠ 也**不能**"按早盘速率外推到全天、再比历史全日均量" —— U 形分布会让外推**系统性高估**。

- 与「尾盘结构」**共用同一份 5 分钟线**，**零额外请求**（新浪一次给约 4~5 天）
- 没有前序交易日 → 量比**显示为空**（不拿 1.0 冒充）
- 只展示、不参与评分
- ⚠ 历史回放日**没有**（分时不可回溯，与尾盘结构同一限制）

**资金流向**：回答「**主力资金最近在进还是在出**」——
逐日主力净额的迷你柱（红=净流入、绿=净流出，由早到晚），配四个数字：
最近一日、近 N 日累计、净流入天数、最近连续流入天数。
⚠ **口径写在卡片上**：展示的是**主力净额 = 超大单 + 大单**（新浪 `r0_net`），
**不是**总净流入（`netamount`）—— 两个字段含义不同，混用会让"主力"二字失去意义。
⚠ **只展示、不参与评分**（尚无历史标定，先积累数据）。

数据来源与节奏：**收盘后（默认 16:05）**抓一次全市场快照落库（新浪，零新增数据源）。快照**不带日期字段**，
故用个股历史端点（带 `opendate`）锚定权威交易日，日期对不上今日则**视为数据未就绪并重试**。
⚠ 时刻两次后挪都由实测驱动：15:20 时新浪当日那一行还没发布（每天必然 missed，且该分支原先不写日志 ⇒ 界面上只剩一句含糊文案）；
改到 16:00 后连续三天成功，但成功时刻是 **16:04:09 / 16:02:05 / 16:02:19**，而 120s×3 的预算从 16:00 起只到 **16:04** 就耗尽
—— 11-03 差一秒当天就没数据，因此起点再挪到 **16:05**（三次尝试覆盖 16:05/16:07/16:09）。
详情页**库优先**，库里不足 20 天时回源一次并落库（该端点忽略 `num`，一次约 1MB）。
⚠ 只覆盖 `securities` 里的 A 股个股（ETF / 指数不显示这张卡）。设计论证见 `docs/specs/README.md`。

**龙虎榜**：回答「**这只票最近一次为什么上榜、谁在买卖**」——
逐条列出上榜原因，配四个数字（净额 / 买入额 / 卖出额 / 龙虎榜成交额占全天成交额比例），
再列**买入前五与卖出前五席位**（营业部名 + 金额，机构席位与股通席位单独标记）。
⚠ **口径写在卡片上**：只含交易所**公布的前 5 个买卖席位** —— 那是龙虎榜的公布口径本身，不是抓漏。
⚠ **同一天可有多条上榜口径**（涨幅偏离 / 换手率 / 连续三日累计…）：**原因全部列出**，
但**金额与席位只取一条**（当日净额最大者，界面上用「金额依据」标出）——
实测同一只票的两条口径金额**逐字段完全相同**（同一批成交按两个口径各披露一次），
逐条展示会像"重复抓取"。席位里的「机构专用」是交易所**匿名化**的机构席位，
同一家机构可能拆成多行 → **行数 ≠ 机构家数**，故不做"机构合计"这类推算。
⚠ **只展示、不参与评分**。

数据来源与节奏：**收盘后（默认 17:30）**按日抓一次全量落库（东方财富数据中心接口，一次 3 个请求拿齐
上榜记录 + 买/卖席位）。详情页**只读库、不回源**（该接口**按日出全量**，为看一只票去拉一整天的数据
是点开详情不该付的代价）。⚠ 17:30 是**估计值**，故"今天还没发布"时**回看最近 5 个交易日补漏**。
⚠ **不做 `securities` 口径闸门**（北交所个股会合法上榜却不在 `securities` 里，用该闸门会把北交所的卡整个隐藏）。
设计论证见 `docs/specs/README.md`。

**涨停统计**：回答「**这只票今天涨停了吗、为什么涨**」。
展示最近一次涨停的日期、**连板数**（首板 / N 连板 / N 天 M 板）、**首次封板时间**、
**炸板次数**、**封板资金**、**行业板块**。

⚠ **清单叫「涨停原因揭密」，但"原因文本"拿不到**（实测三处源都无该字段）→ 改做**结构化的"为什么涨"**：
连板数 / N天M板 / 封板时间 / 炸板次数 / 行业 / 封板资金（**结构化证据比一句题材文本更可核对**）。

⚠⚠ **只覆盖最近约 10 余个交易日**（源的限制，实测 `09-01` 就取不到了）→
卡上写「库内最近 N 个交易日」，否则"没有记录"会被读成"从来没涨停过"；
库里一天都没有（任务还没跑过）→ **整张卡不显示**（显示"没有涨停记录"会让人以为抓过了）。
⚠ **历史回放不能回放它**（覆盖窗口太短，补不了）。
⚠ 只展示、不参与评分。

数据来源与节奏：**收盘后 15:15** 抓当日全量落库（东方财富涨停池接口，已用 provider 的
新子域）。⚠ 选 15:15 而不是像龙虎榜那样等 17:30 —— 涨停在 15:00 收盘时定稿
（那是**行情自身的状态**），而龙虎榜要等**交易所发布**。同样有**回看 5 个交易日补漏**。
设计论证见 `docs/specs/README.md`。

⚠ 看板的「昨涨停表现」**不依赖这个 15:15 任务**：盘中 09:30 起每 60 秒用实时行情独立计算
（只进内存、不写库）；15:15 任务仍负责收盘定稿与落库。开盘时若库里没有前一交易日的涨停池，
会向源补取一次（源覆盖约 10 个交易日，补不到就如实提示缺失）。

**昨涨停表现**（功能 A）：市场**打板情绪**读数 —— 昨日涨停池里每只票
今日的涨跌幅统计（**平均 / 中位 / 晋级率 / 亏损面**），看板一张卡 + 近 20 日迷你趋势。
回答「昨天追涨停的人今天赚钱还是亏钱」。

⚠ 输入**全是已有数据**（昨日涨停池 + 今日行情），零新数据源；不占独立调度项。
**盘中 09:30–15:05 每 60 秒**用实时行情算一次（`ZtSentimentLive`，只进内存，失败保留上一笔）；
**15:15 收盘任务**用收盘价算最终值并落库（情绪算失败不影响涨停池本身的落库与任务状态）。
⚠ 「昨日」= 交易日历的**前一交易日**（周一的情绪对应上周五的池子），与复盘同源。
⚠ 停牌/缺价**单独计数、不进均值**（否则停牌 0% 把情绪拉平）。
⚠ 晋级按**该票自己的板块上限**判（用昨日封板涨幅反推 10/20/30 档，不硬编码代码前缀表）。
⚠ **只展示、不进评分、不进大盘灯**（与基本面/资金流同一姿势）；
喂大盘灯需要新参数版本 + Spearman 相关性检查（与现有涨跌比大概率 ρ>0.6），留作后续迭代。

**板块热度**（功能 B）：独立页面 + 看板「领涨板块 Top5」卡。
行业板块当日截面：涨幅 / 主力净流入 / 板块内涨跌家数 / 换手 / 领涨股，可按涨幅或净流入排序。

⚠ 数据源是东财 `clist` 板块域（`fs=m:90+t:2`，实测 496 个板块）——**混了申万一/二/三级粒度**
（「电视广播Ⅱ」「电视广播Ⅲ」「传媒」并存），**不要**拿板块名与涨停池的 `hybk` 做等值 join
或涨停池 `hybk`（实测被**截断到 4 个汉字**）做 join。个股归属交叉留给未来的成份接口。
⚠ **源只有当日截面**（clist 无 date 参数）→ 没有涨停池那样的回看补漏，缺一天就永久少一天；
落库 `board_heat` 正是为了攒历史名次。休市时段源给 `"-"` 哨兵（实测盘前），解析层折成空值。
⚠ 抓取纪律与行业刷新同源：`pz=100` 分页 + 秒级退避 + 全局限速 + 完整性校验（半截整轮作废）。
⚠ 看板 Top5 盘中走**单页轻量请求**（`pz=6&fid=f3`，09:00–15:00 每 60 秒，只进内存）；
全量 496 个板块仍由 `BoardMonitor` 每 5 分钟刷新、15:10 调度任务定稿落库。
⚠ 只展示、不参与评分。

K 线交互：**以鼠标位置为中心**缩放（滚轮 / 捏合）、鼠标左键拖拽平移、
触控板双指左右滑动平移、拖到最左自动加载更早历史；**任何缩放级别右侧都不留空白**
（尾部留白为 0，缩到最小 = 已加载历史无缝铺满一屏）；副图刻度与图例按 `X万 / X亿` 紧凑显示，
**成交量（手）/ 成交额（元）** 在「设置 › 显示 › 图表」里切换（分时与日/周/月 K 同口径；
成交额取腾讯日/周/月线第 9 字段万元并换算为元；整批无成交额（新浪兜底 / 部分市场）时副图自动回落到成交量）。

**新手引导**：首次启动 4 步引导（核心策略 → 每日节奏 → 信号纪律 → 开始前两件事），
可从设置页重看。

**长任务等待指示**：等待期用**点阵动效**（本地 vendor 的 ThinkingOrbs），
按"正在做什么"选语义 —— 扫描 / 验证 `.searching`、三轮对比 / 列表拉取 `.connecting`、
预判 / 调参 `.solving`、复盘 `.composing`、迭代 `.weaving`。
**只换原来那个转圈图标槽位**：文案、耗时提示、语义色（执行中=蓝）一律保留，
所以「完成 / 异常 / 待运行」仍由图标 + 语义色表达，动效只表示"在忙"。

⚠ **三处有意不用它**：K 线 / 分时的骨架屏（那是"即将出现"，不是"在忙"）、有百分比的确定性进度、"待运行 / 等生成"的静态空态。
⚠ 动效是**灰度墨点、不参与状态语义**（跟随明暗外观、不读 `Sem`/`Tok` 色板），遵循系统「减弱动态效果」（自动静止一帧）。
⚠ 本项目**不做读屏无障碍**（产品决策，代价见 `docs/specs/README.md`）；静态护栏 `a11y_absent` 盯着不许加回来。
白名单与理由见 `docs/specs/README.md`，越界由静态护栏 `orb_whitelist` / `orb_layering` 拦下。

## 十一、数据与备份

**所有业务数据都在一个 SQLite 库里**（`~/Library/Application Support/Selected/selected.sqlite3`，
WAL 模式，全本地不上传）。表结构见 [README](../README.md#数据目录)。

- 数据库是**唯一不可再生的资产**，每次打包发布自动归档（含 WAL 一致性快照，滚动保留 5 份 ——
  实测每份 ~76M，原写 30 份是按"每份 0.5M"估的，低估 150 倍）
- 启动时做完整性自检（`PRAGMA quick_check`），损坏时明确提示恢复路径（不表现为"页面全空"）
- 首次启动自动完成初始化：建库 → schema 迁移（幂等迁移条数以 `engine/params/db_schema_export.json` 的 `migration_sql` 为准，失败不推进版本号并留痕）→
  注入出厂参数版本
- ⚠ **App 内不提供"导入历史数据"**（2026-10-27 删除）：本应用没有对应的导出功能，
  那条路径读的是早期版本在同一台机器上写的目录，早已不再产生。
  **恢复走文件**：`scripts/backup_data.sh` 归档、把归档复制回数据目录即恢复（恢复演练也在该脚本里）。
- ⚠ **没有"在 Finder 中打开数据目录"的入口**（有意不做）。需要时手动开「访达 → 前往 → 前往文件夹」，
  输入 `~/Library/Application Support/Selected`。

### 归档的两道保护

`scripts/backup_data.sh` 除"备份与线上一致"的自检（`integrity_check=ok` 且 `LIVE_N == BAK_N`）外，
另补两道（滚动窗口只有 5 份，一次空构建就会**挤掉最老的好归档**）：

1. **空库保护**：即将归档 0 行、而归档目录里已有历史归档 → **拒绝产出并报错**。
   判据依据是：这种情况几乎必然是"库被重建或迁移失败"，而不是"用户主动清空了全部数据"。
   要归档空库需先手动移走旧归档（显式确认）。
2. **内容去重**：签名取"关键表的行数 + 最大自增 id / 时间戳"（能同时捕获新增与就地更新），
   与上次成功归档的签名相同则跳过 —— 把滚动窗口留给**真正不同的状态**，
   而不是每次构建都占一份。任一表不存在（老库）时签名为空，此时**不做去重**（宁可多备一份）。

### 迁移与备份的**安全不变量**（改这块前先读）

以下几条是从同类项目的真实事故里总结的，改动迁移/备份/恢复逻辑前逐条对照：

1. **绝不删除旧数据文件** —— 留作永久安全网。最坏情况下用户还能手动换回去。
2. **先拷到临时名，全部成功后再原子改名** —— 例如 `x.migrating` → `x`。
   改名动作只应在**所有**临时拷贝都成功之后发生；中途崩溃不应留下"看起来已完成"的状态。
3. **伴随文件的改名有顺序** —— 数据库的"是否存在"由**主库文件**决定。
   若先改主库名再崩溃，下次启动会认为"已迁移"，而 `-wal` / `-shm` 还叫临时名 →
   SQLite 打开的是一个缺少 WAL 的旧快照。本项目的做法是
   `-wal` → `-shm` → 主库（与同类项目的经验一致）。
4. **不要把库放在 `~/Library/Application Support/` 根目录** —— 那是**任何**非沙箱应用的
   默认落点，别的应用一跑就可能覆盖同名文件；某些平台的持久化历史逻辑还会把
   认不出的实体当"已删除"而**截断表**（静默丢数据）。
   本项目已按应用名分目录（`…/Application Support/Selected/`），**保持这一点**。
5. **迁移失败不推进版本号，并留痕** —— 否则下次启动会跳过失败的迁移，表永久缺失。
   本项目 `meta.schema_version` 水位 + 事务 + `data_source_logs` 留痕已满足此条。
6. **归档走在线备份 API，不要拷主库文件** —— WAL 模式下未 checkpoint 的写入不在主库文件里，
   直接拷会**静默丢数据**（实测复现：主库 0 行 / 实库 1 行）。
7. **shell 脚本注意 `set -euo pipefail` 与 `ls` 的交互** —— `ls` 无匹配时返回非零，
   在 `pipefail` 下会让**整条管道失败并静默中止脚本**（表现为"打印到一半就没下文了"）。
   需要"计数匹配文件"时用 `find … | wc -l`，不要用 `ls glob | wc -l`。

## 十二、技术架构

### 全原生

运行期**无 Python 子进程、无长驻服务、无内嵌解释器**（包体约 **18 MB**：可执行文件约 17 MB、
`Resources/` 约 0.7 MB）。原生失败**直接报错并交由调度器重试**，不做 CLI 回落
（回落只会把原生 bug 掩盖成"照样能用"）。

### 分层与实体层

代码分两个 target：

- `Sources/SelectedCore` —— 引擎 + 数据层，**只许** `import Foundation` / `SQLite3`
  （不得碰 SwiftUI；`CoreLayeringTests` 钉死这条边界）
- `Sources/SelectedApp` —— SwiftUI 界面与调度
- `Tests/SelectedCoreTests` —— 纯 Core 逻辑的单元测试

#### 大文件按**类型/职责边界**拆分

大文件按职责拆开（如 `DataSources` + Quotes/Lists/Kline 三个 extension、
`Store` + Store* 各 extension、视图按页面/分区拆文件）。

⚠ Swift 的 `private` 是**文件作用域**、**存储属性不能声明在 extension 里**
⇒ 跨文件成员从 `private` 放宽到 **module-internal**（**对 App 仍不可见**，`internal` ≠ `public`）；
放宽的是"模块内可见性"不是 API —— 两个 target 的外部接口没有任何变化。

**引擎输出到界面走"实体"，不再用字符串键去 poke `JSONValue`**：写 `ScanPick.code` /
`ScanResult.stats.tier1Count`，而不是 `json["code"]` —— 键名拼错 = **编译错误**、引擎改键名 = **测试红**。
实体**包着原始 `JSONValue`**（不是纯字段 struct），因为引擎 JSON 宽松（`110` 也可能是 `110.0`）而严格
`Codable` 会把"形态差异"变成静默行为变更。新增字段必须同步声明键名，否则会被黄金夹具的键覆盖测试拦下。

> 决策与全部踩坑记录见 [specs/README.md](specs/README.md)。

### 指标库（黄金夹具批）

**纯计算指标库**（服务指标筛选页），全部 clean-room 独立实现：

- `SelectedCore/IndicatorPrimitives.swift` —— 共享原语（SMA/WMA/EMA/RMA/滚动极值/
  总体σ/TR/ROC/序列算术）。**平滑种子与起点口径由黄金夹具锁定**（EMA 种子=前 n 项 SMA、
  KAMA 种子=索引 er−1 收盘价、σ=总体口径等），不是教科书默认。
- `SelectedCore/TrendIndicators.swift` —— EMA / MACD / HMA / KAMA
- `SelectedCore/MomentumIndicators.swift` —— RSI(Wilder) / Stochastic / StochRSI / PPO / AO / UO
- `SelectedCore/VolatilityIndicators.swift` —— ATR(SMA) / Bollinger 系 / Donchian / Keltner / SuperTrend / Ulcer
- `SelectedCore/VolumeIndicators.swift` —— VWAP / CMF / EMV / FI / MFM / MFV
- `SelectedCore/IndicatorRegistry.swift` —— 22 个指标的元数据注册表（id/分类/显示名/默认周期/口径一句话），
  P1 快照 Job 与 P2 筛选页的接口；契约测试钉死"实现↔登记"双向一致

**黄金夹具**：`SelectedApp/Tests/SelectedCoreTests/Fixtures/indicator_golden/<分类>/*.csv`，

未翻译其任何源码。夹具值舍入到 2 位小数、预热段为 0/空占位，比对从首个有效行起
（`Tests/SelectedCoreTests/IndicatorGoldenSupport.swift`）。

**已知口径分裂（两份并存、各有测试钉死，不许"顺手统一"）**：

| 量 | 既有实现 | 指标库新实现 | 原因 |
|---|---|---|---|
| RSI | `Oscillators.rsi` 简单均值（评分链路） | `MomentumIndicators.rsiSeries` Wilder | 夹具口径 + StochRSI 定义需要 |

SuperTrend 的夹具口径是 **HL2 基准 + HMA(TR) 带宽**（与通达信常见 EMA 版不同），
已写进函数注释。KST 未入首批：其夹具值与上游当前实现无法复现（疑似旧版本生成），
按"每个指标必须有可复现夹具"纪律移除。

#### 指标快照 Job（P1）

收盘后把**全市场 × 22 指标末值**批量落库，供筛选页（P2）秒开查询：

- `SelectedCore/IndicatorSnapshotJob.swift` —— 调度任务 `indsnap`（**15:25**，涨停统计之后、
  迭代之前；资金流已挪至 16:05，二者无先后依赖）。数据源两道拼合：`history.sqlite3` 的 `daily_bars`（volume=**手**）
  + 当日收盘行情合成今日 bar（**不 ×100**，`EngineIndicators.appendTodayBar` 是引擎"股"
  单位体系，不可复用）。三道闸门：交易日 / 新鲜度（缺口 >1 个交易日或库空 → 抛错，
  **文案指向"设置 › 历史回放"**——需要用户动作的失败不写"稍后重试"）/ 行情覆盖率
  （复用 `ScanRunner.minQuoteCoverage` 0.93）。停牌/脏报价 → 今日 bar 造不出 → **整行不写**
  （陈旧值冒充今日是禁区）；新股预热不足 → 写行、列 NULL。
- `SelectedCore/IndicatorSnapshotStore.swift` —— 主库 Swift-only 宽表 `indicator_snapshots`
  （PK `(trade_date, code)`，36 个值列 + `fetched_at`；列名由 `IndicatorRegistry.outputs`
  单一来源生成，契约测试钉死"注册表↔DDL↔Job 末值键集"三方一致）。**整日重插**
  （盘中手动=盘中快照、收盘调度=终态覆盖，同板块热度纪律）。读侧纪律：值列 `as? Double`
  禁 `doubleOrZero`（NULL=算不出，不是 0）；`ranking` 列名只走白名单。
- ⚠ **前置条件**：`daily_bars` 只由设置页"历史回放"写入（新装机器为空）——
  没回放过就没有快照，Job 会以"去回放"的可重试失败报红，这是设计不是 bug。
- 已知盲区（有意接受）：回放整体停摆时个股/指数同日同旧，缺口恒 0，指标窗口含"洞"
  （与个股长期停牌同类）；P2 页面按 `trade_date` 自证新鲜度。

#### 指标筛选页（P2）

侧栏第三项（看板、自选之后），把快照变成**多条件筛选器**：

- `SelectedCore/IndicatorScreener.swift` —— **规则表**：注册表 22 指标一指标一判据
  （`filter` 当日谓词 / `cross` 与前一快照日的穿越（金叉）/ `sort` 无阈值强弱排序）。
  判据全部基于收盘定稿快照，**只作筛选展示、不进评分**（方向未经本项目标定）。契约测试钉死：
  指标↔规则一一对应、规则 SQL 只引用白名单列、`p.` 前缀必须声明需要前一日。
- **多条件 AND**：`IndicatorScreener.screen(indicatorIds:date:limit:sortBy:)` 一次查询返回
  "同时满足全部条件"的股票；每条件一列（该规则的排序键值），排序在 SQL 里做（`NULLS LAST`），
  不是只重排前 300 行。界面一次最多 `IndicatorScreener.maxConditions` = **6** 个条件。
- **单独命中数**：勾选面板与目录右侧显示每条规则在当前快照日的命中数（一次 `SUM(CASE…)` 出 22 个数）。
  这些条件会互相矛盾——实测 2026-10-23：`EMA上穿 + RSI超卖 = 0`（两者单独 893 / 802，超卖股全在均线下方），
  而 `EMA上穿 + CMF > 0.1 = 433`。0 命中页会给出"去掉哪一条能出多少只"的实查建议。
- 快照宽表补两个**基础列**（非指标，进白名单与 DDL）：`close_value`（今日收盘，
  `收盘>均线` 类比价基准）与 `atr_sma_percent`（ATR 占价%，跨标的可比的高波动判据）。
- **唐奇安通道**的「创 20 日新高」与**前一快照日**的上轨比（`close > p.donchian_channel_upper`）：
  当日上轨含当日 high，`close > 当日上轨` 数学上不可能，旧规则恒命中 0（2026-10-26 实测 5217 只全空）。
- `Views/IndicatorScreenerView.swift` —— 快照行 + 条件条（选择指标 popover / 已选 chips / 筛选）
  + 可勾选目录（带命中数）+ 结果表（**收盘价 / 当日涨跌幅** + 每条件一列，点表头换排序键）。
  结果表**铺满分摊**：固定列之外名称拿约 38%、指标列平分其余（名称 140–300、指标 72–260），
  列太多/窄窗口放不下时横向滚动兜底——不留"某一列特别空"或"表尾一大片空"。跟随 `viewDate`；
  所选日无快照时回落到**不晚于它的最近快照日**并在页顶明示（不静默拿别的日子冒充）。
  列表上限 300 只（如实标注）；穿越类规则在库里没有前一快照日时命中数为「—」而不是 0；
  点结果行复用全局 `showStockDetail`。
- **设置面板（齿轮）**：判据阈值（4 项）改完即时生效；指标周期（33 项）在关闭面板后触发一次
  全市场快照重算（约 1 分钟）；**历史日不重算**——面板会写明"周期已保存，回到最新交易日后生效"，
  不再弹"不可重算"的报错。重算完成后页面靠 `Store.indicatorSnapshotRevision` 自动重载
  （**不能只看覆盖只数**：重算前后通常都是 5217，`onChange` 不会触发）。
- **超买超卖线（25 项）折叠在设置面板末尾**并标注"仅影响个股详情页的 Zone 判读，不影响本页筛选"：
  它们只由 `StockDetailSheet` 的 `IndicatorParamStore.oscConfig()` 消费，和筛选结果零关系。
- **板块矩阵（板块热度页）**：表头与所有数据行放在**同一个 `Grid`** 里（列宽只有一份，避免表头/数据各写一套
  HStack 后整体错位）；每页行数由**卡片实测高**倒推（右侧详情卡更高把左卡撑高时，补上这部分行数，
  上限 +8 行防自激），不再按视口估算留出底部空白。行高/表头/分隔线 2026-10-26 起读全站同一套
  `TableMetrics` + `TableRule`（原先它自己写死 24pt 行高、用 `Divider()`，是"还是没统一"的那一处）。
- **表格统一（2026-10-26）**：复盘验证（预测 vs 实际）、历史迭代（四层胜率明细）、调优（回测对比）、
  三轮对比（逐标的轨迹）四处原生 `Table`（带斑马纹与列竖线）全部改成 `SharedDataTable`；选股结果的指标列改成弹性分摊、
  早盘预判的统计格铺满整行；指标筛选结果表与板块矩阵两处**手搓表格**（需要横向滚动 / 表头排序按钮，套不进组件）
  改为直接读同一套 `TableMetrics`（表头 11pt/28、行 12pt/30）与 `TableRule`，不再各自写行高、
  也不再混用 `Divider()` 与 `Divider().opacity(0.35)` 两种分隔线。
  统一口径：表头 11pt/28、行 30、数字右对齐、只有行间 1px 发丝线，
  **无斑马纹、无列竖线、无表头底色**；列宽不再由单个名称列吃满——固定列之外，桌面余量按
  「名称 2 : 其他 1」摊给所有列。
  ⚠ 这套口径由护栏 `table_geometry` 钉住（几何常量只许定义一份 + 在册表格页必须真的引用），
  不是靠注释提醒。
- 测试互踩教训：**库级测试必须收进同一个 `.serialized` 套件** ——
  两个套件并发 `setenv("SELECTED_DATA_DIR")` + 共享写连接单例会交叉到
  "database is locked / no such table"；纯契约用例与碰库用例分文件分套件。

#### 参数中心重构 R0：B 域独立存储

**三域纪律**（改筛选阈值不该生成选股版本、进调优空间）：

- **A 选股参数**（打分/过滤/档位/预判/迭代）→ `param_versions` 版本线，语义不变；
- **B 指标筛选参数** → 新独立表 `indicator_params`（当前值）+ `indicator_param_changes`（变更流水），
  由 `SelectedCore/IndicatorParamStore.swift` 读写（自持只读连接，进换库失效清单）；
  **不进选股版本列表、不进调优**。键与区间/默认的唯一来源是
  `SelectedCore/IndicatorParamSpec.swift`（三段：`screen.*` 判据阈值 4 项、
  `period.*` 指标周期 33 项、`osc.*` 超买超卖线 25 项）；契约测试钉死
  spec 默认 == 规则表默认 == 注册表 defaultPeriods == `Oscillators.Config` 出厂值。
- **C 保持代码**：定义性判据（ppo>0、%B>1）、形态阈值（未标定）、强度权重、覆盖率闸门 ——
  改了是"改系统"不是"调参"，不给按钮。

要点：
- **读回落**：缺键/脏值 → 默认值（写侧守门：未知键/越界抛错；"恢复默认"= 删行）。
  从不写默认值占位行，表里只有用户显式改过的键。
- **周期接通快照**：`IndicatorSnapshotJob.snapshotValues` 全部指标显式传
  `IndicatorParamStore.period(...)`；**改周期在关闭设置面板时触发一次全市场重算**
  （约 1 分钟，不做每改一下重算一次）。
- **编辑入口在筛选页**（右上「设置」→ `Views/IndicatorSettingsSheet.swift`）：
  三段就地改、改即生效、底部变更流水；与选股参数中心彻底解耦。
- Oscillators 阈值接通：个股详情「技术判读」卡的 Zone 线读 `oscConfig()`（缺省回落出厂
  Config，`.task` 缓存进 `@State`，body 不查库）。
- A 域撤出：选股 schema 与出厂 JSON 里**不再有 `screen` 组**
  （validate 忽略未知键 → 存量残留键无害，无需清理迁移）。

### 界面主题（单套玻璃 · 浅色 / 深色）

颜色只有两份定义：**色值**在 `Views/Palette.swift`（唯一 hex 来源），**取用出口**在 `Views/Tokens.swift`。
业务色走 `Sem`（涨跌/灯级/信号/风险/状态/品牌 + `upFill`/`brandFill` 两个填充位），
表面与线条走 `Tok`（窗口底/行底/嵌底/胶囊/细线/描边/骨架/占位/阴影/均线），
视图里不再就地写死颜色。
**语义色的"底"（徽章 / 标签 / 提示块）走 `Tok.tint(color, .block/.chip/.strong)` 三档唯一出口**
（`block` 0.08 / `chip` 0.12 / `strong` 0.18）。

2026-10-30 起**不再提供配色切换**：全站只有一套玻璃主题（改造前的原色），
侧栏底部的「配色 · 档名」入口与五档色板已删除；旧的 `palette` 持久化键在启动时一次性清除。
- 色值仍是**四态**（浅 / 深 × 基础 / 高对比度）+ 一对**中性梯度**实底（见下）。
- `Sem.*` / `Tok.*` 是 `static let`：`Color.adaptive` 只建一次，外观切换（自动/白天/黑夜）
  仍由 `NSApp.appearance` 承载，不需要重建视图树。

**两枚中性基色**：`Tok.windowBacking`（整窗半透明底衬，浅 0.74 / 深 0.80）与 `ThemeColors.neutral(...).card`
（后者只是 `sem_contrast` 的对比度基准，不填卡片）。
**方向恒为浅档卡面亮于托底、深档卡面暗于托底**（`theme` 自检第 7 组逐档遍历）。
玻璃那一层**一律不上色**（`.tint()` 没有浓度可调，"在玻璃下垫一层色"等价于给玻璃上色）：
`WindowGlass` 是「半透明底衬 + 原生 glass」且未上色；`windowBacking` 只决定透多少；浮动面板、sheet 同理。
⚠ 页栏与内容**都不带自己的底**，直接坐在同一层玻璃上（老板 2026-10-23 逐版实机验收定稿：
「一个大的作为底色」→「其他页面也全都去掉，内容直接放」）。
两套色值都由 `NSColor` 动态色承载（本项目无 `.xcassets`），随系统外观即时切换；
**主窗口侧栏左下角**（调度状态行下面）三个并排的小图标可切 **自动 / 白天 / 黑夜**
（设置页不再有第二个"外观"入口 —— 同一动作不留两条入口）。
⚠ 是**原生分段 Picker**：标签用 `.labelsHidden()` 隐掉（macOS 的分段 Picker **会把标签画出来**），
并与上面的调度状态行**居中对齐**。底层是 `NSApp.appearance`，覆盖所有窗口与菜单栏菜单，
图表 `GraphicsContext` 里的颜色也跟着解析。⚠ **点哪个是哪个**（不是循环按钮）：一眼看得到有哪三档、
也看得到当前在哪档，且一步到位；选中态由系统分段控件提供。

**按钮只有四个角色**（唯一出口在 `Views/Components.swift`）：
主操作 `btnPrimary()`（实底品牌蓝，每个单一动作面最多一个）/ 次操作 `btnSecondary()`（系统灰描边）/
破坏性 `btnDanger()`（红字描边，确认弹窗里可用 `btnDangerFilled()` 实底）/ 图标 `btnIcon(_:)`（无边框 + 前景色）；
同一颗按钮随状态换角色时用 `btn(_:)`（如"加自选 / 去掉自选"）。
⚠ **语义色（涨跌 / 灯级 / 信号 / 风险）不上按钮** —— 那是数据展示的颜色语言，用在按钮上会让"红色"
既表示"上涨"又表示"危险"。护栏 `button_style` 把"唯一出口"钉死。
⚠ `btnPrimary`/`btnDangerFilled` 走的是 **fill 位**（`Sem.brandFill`/`Sem.upFill`）而不是 text 位：
一支色不可能同时满足"深底卡片上作文字 ≥4.5:1"与"作填充时压得住白字 ≥4.5:1"
（抬亮 `brand` 修前者会把白字从 3.88 打到 2.83）⇒ 拆两档，填充位钉住原色、按钮像素不变。

**分数徽章读哪套口径** ——
`ScoreBadge` 有两种取色入口：`Sem.scoreColor(score, tier1:, tier2:)` 按**当前生效门槛**重算，
`Sem.scoreColor(tier:)` 按**落库时分的档位**。
⚠ **选股结果页必须走后者**：那里的分组本来就是落库 tier（`ScanResult.tier1/tier2/tier3` 三个数组），
颜色若仍按今天的门槛算，就会出现「二档候选卡里 58/53 分被画成回避绿」——
同一行里"它属于二档"和"按今天的尺子它不够"互相打脸。
⇒ 由 `pickSection(storedTier:)` 一路传到 `pickScoreCell`，颜色与分组同源；
"达标"胶囊同样以 `storedTier == 1` 为准。
个股详情 / 自选行内 / 持仓区**没有落库档位**（那是实时分数对实时门槛），继续走当前门槛重载 ——
这是有意为之，不是漏改。要看新参数怎么判历史那批，去参数中心重跑。
副作用：改门槛后历史卡的颜色不跟着重算 = **归档快照**语义。

**`theme` 自检八组断言**：明暗自适应 / 浅色档钉为原色号 / 语义色对窗口底 ≥3:1 / 表面层级严格递增 /
语义入口映射 / 外观三档 / **中性梯度方向** / **窗底基色下限**。
⚠ 第 7 组断言的是**方向**（浅档 `luminance(card) > luminance(glass)`、深档反向），**不是**某个对比度阈值 ——
对比度函数是对称的，把两枚值对调照样返回同一个数，正好放过它要防的"卡片陷进底里"。
2026-10-23 参照物从已删的 `window` 换成 `glass`（卡片现在直接坐在玻璃上）；带宽不再判：
深档最弱一对实测只有 1.003:1，钉阈值等于逼着改色，分界由 `CardSurface` 的 hairline 撑。
⚠ 第 8 组是**自包含**的（不依赖别的 token）：浅档底衬基色与纯白、深档与纯黑必须拉开 1.12–1.75:1，
再加"极差通道须与本档卡面同向"（不许给玻璃上色）。三条各做过变异测试（对调 / 洗成近白 / 换冷色相）确认会报红。

其余把"唯一出口"钉死的静态护栏（`theme_source` / `theme_accent` / `theme_tint` / `chart_param` /
`sem_contrast` / `bar_separation` / **`no_zebra`**：视图层不得出现隔行上色或 `zebra` 开关 /
**`table_geometry`**：表头 28、行 30、hairline 只在 `Components+DataTable.swift` 定义一份，别处不许再抄一份行高，
原生 `Table` 的 `.tableStyle` / `alternatesRowBackgrounds` 不得回潮，且在册表格页必须真的引用这套 token /
**`row_cursor`**：挂了 `.onTapGesture` 的视图文件必须同时挂 `.clickableRow()`（`Components.swift`，
内部走 macOS 26 `.pointerStyle(.link)` + `MousePressCenter` 按下轻淡）—— 淡底说"鼠标在哪"，手型光标才说"这行能点"，
按下轻淡说"这一下收到了"；按下态只许靠本地事件监视器（只观察不吞事件），
**不许**用 `onLongPressGesture(minimumDuration: 0)` / `DragGesture(minimumDistance: 0)` 去取
（那是往行的 `onTapGesture` 旁边再塞一个识别器抢同一次点击，离屏验不了、只能真机点）；
`NSCursor.push/pop` 不得回潮（行在悬停中被销毁 ⇒ pop 不掉、光标卡住），豁免只有 `FocusDismiss.swift`）/
**`page_merge`**：三轮对比并入选股结果时间线（2026-10-29 M1 + M2）的接线必须齐 —— `enum Page` 不许再有 `compare`、
枚举 case 数 == ⌘ 菜单按钮数 == 详情分派 case 数（「声明顺序 = 侧栏顺序 = ⌘1…⌘9」不再只靠注释维持）、
`CompareSection` 必须真被结果页渲染且段选器上有 `.tag(Leg.compare)` 那一格、通知深链四段链
（Scheduler 落点 → `userInfo["section"]` → `requestCompareLeg()` → 结果页 `leg = .compare` 并作废）一环不许断，
外加**链路状态条不得回潮**（老板判「这一行去掉」：页内进度看按钮转圈，全局看侧栏底部调度状态行））

**动效口径（克制）**：只做"数据 / 状态真的变了"时的轻量过渡，不做装饰性动效。
曲线与时长一律取 `Components.swift` 的 `Mot` 档位（按用途命名，`motion_whitelist` 拦散写）——
调手感改那一处即可，不必在视图里逐个找数字。
落地清单：统计数字滚动（`RollingNumber`，含涨跌 `PnlText`）、自选与持仓列表行悬停（整块高亮 + 补出「移出 / 清仓」行内按钮，
宽度恒定不推动列）、切页与切分组 150ms 淡入、长页顶部滚动进度细线（滚离页首后时间戳退让）、
提示（toast）最多同屏 3 条（**无关闭按钮**）。
⚠ **位置：顶部水平居中**（top 56 / 宽度上限 380，2026-10-27 老板拍板改回居中）。
判据是"toast 一会就消失，压一下下面的内容没影响"——这对 `success`/`info`/`warning` 成立，
对 **`error` 不成立**（它钉住到点不走）：在自选页可能长时间压住搜索框、在对比/复盘页压住页首内容。
这是**已知代价**，不是漏网。曾为避开它们挪到右上角（2026-10-23），但那一版有个几何 bug：
胶囊套在 `.frame(maxWidth: 380, alignment: .leading)` 里贴右 ⇒ **短文案被左对齐塞进 380pt 透明框**，
视觉上"越短越往中间飘"（胶囊左缘落在 724pt，截图实测 728pt）。改居中后该偏差不存在。
⚠ **收尾三档**（判据唯一实现 `SelectedCore/ToastPolicy.swift`，可单测）：
`success` **2.0s** 自动消失（通过/正常）· `info`/`warning` **3.5s** 自动消失（中性提醒）·
`error` **不自动消失**（告警/警报）—— 点窗口任意处才走（`NSEvent` 本地监视器，不吞事件）。
⚠ **五档语义色**：`success` 绿 / `info` 蓝 / `warning` 橙 / `error` 红，
**底色、描边、图标都带该档的颜色**。
⚠ **`loading` 档**（长任务占位）：**转圈**而非静态图标（静态符号会被读成
"某一步已完成"）；它按 300s 兜底收尾 —— 完成时由调用方用**同一 key** `show`
一次**原位替换**（300s 只是调用方没回来的兜底）。首批调用点：设置页「个股档案」的
指数成份 / 基本面刷新（卡上转圈只在设置页可见，切页后全局 toast 是唯一"还在跑"信号）。
⚠ 调用点必须**显式标档**：失败类用 `.error`、部分成功 / 前置不满足 / 口径提醒用 `.warning`、
中性信息用 `.info`，只有真成功才走默认的 `.success` —— 护栏 `toast_styled` 钉住这一点。
⚠ **toast 没有关闭按钮**：那个 × 既占宽又暗示"要手动关"。钉住的 `error`
收尾方式是"点别处即走"，仍不需要瞄准控件 ⇒ 依旧不加 ×。
⚠ **钉住的 error 不参与"最多 3 条"的淘汰**（否则下一条一来告警就被挤没，"不自动消失"形同虚设）；
全是钉住条目时宁可临时多占一条，也不静默吞掉告警。

**主窗口「关闭 = 最小化」的接线必须完整（`close_minimize`）** ——

否则会静默丢掉工具栏/状态恢复等行为），再把守卫**强引用**装到主窗口上（`NSWindow.delegate` 是 weak），

不放它出来，`isVisible` 仍为 false）。

③ `AppShellView` 上真的挂了 `.mainWindowCloseGuard()`（空转检测）。

⚠ 实测确认：红叉与 `performClose`（`Cmd+W`）都走 `windowShouldClose`；转发生效；`NSApp.terminate`（`Cmd+Q`）**不经过**它。

**分时成交量柱的红绿方向（`minute_volume_open`）** ——
分时的 `open` **不是开盘价**，而是"**本分钟的涨跌基准**"（上一分钟价；首根用昨收）：
图表库的成交量柱按 `open > close` 判跌（绿）、否则判涨（红），最新价胶囊按 `close >= open` 判色。
⇒ 若把 `open` 也写成现价，`open == close` 恒成立 → **成交量柱永远全红**，
而且编译通过、全部单测全绿、其余护栏一条都不报。
护栏钉四条：首根基准 = 昨收（`var refPrice = previousClose`）、`open` 填 `refPrice`、
基准逐根推进（`refPrice = p.price`）、以及反向断言"`open: p.price, close: p.price` 不许再出现"
（那正是 bug 的原形态；反向判据先剥整行注释）。
⚠ 最新价胶囊另走 `latestPricePositive`（分时按**相对昨收**着色）—— 不能复用 `close >= open`，
否则胶囊会随最后一笔的涨跌变色，与 A 股"按当日涨跌"的惯例冲突。

**涨跌数字恒带正负号（`signed_change`）** ——
"红涨绿跌"**不是一条对所有人都成立的编码**：用 Viénot–Brettel 二色觉模拟实测全站涨/跌文字色，
涨/跌两支文字色的 deutan ΔE 只有 **0.030–0.082**（本仓自己的判据是 <0.10 = 不可分），
明度差 ΔL 也只有 0.001–0.033 —— 后者是**故意的**（text 档齐平，数字列才不会因颜色跳行），
代价就是色觉障碍下这两支是同一个橄榄色。⇒ 方向必须由**符号**承载，
而"为了排版把 `+` 去掉"这件事编译不报错、单测全绿，只能靠源码钉。
判据：凡 `String(format:` 的入参出现涨跌字段（`changePct` / `changePercent` / `pnlPct` /
`dayPnlPct` / `gainPct`），格式串必须含 `%+`。
⚠ **同时断言命中数 ≥ 15**：字段改名或路径漂了会让 grep 命中 0 行而"全绿"通过 ——
与 `sem_contrast` 正则版同一类失效（护栏空转比没有护栏更糟）。

**比例条图形档的分离度（`bar_separation`）** ——
涨/跌的 **text 档明度是刻意齐平的**（ΔL 0.001–0.033，为的是数字列不因颜色跳行），
代价是两支在二色觉下糊成同一种橄榄色（deutan ΔE 只有 0.030–0.082，本仓判据 <0.10 = 不可分）。
`BreadthBar` 是全仓**唯一**"两枚语义色相邻成对、要靠颜色分辨谁是谁"的元素，
所以给它单独一档**图形档**（`Sem.upGraph` / `Sem.downGraph`）：同色相同彩度、只挪 OKLab L，
把 deutan ΔE 拉到 ≥0.115。
护栏逐档实算四件事（2 组 = 浅/深）：① deutan ΔE ≥0.115；② 两支对**卡片实底**
（取"纯底"与"叠一行底色"里更差的那个）≥3:1；③ **只许挪明度** —— 与同名 text 档比色相角差 <2°、
彩度差 <0.01（改色相等于改语义，与 `sem_contrast` 同一条纪律）；④ 覆盖数必须等于预期，少一组就是空转。
⚠ **为什么必须有这条**：图形档的值比 text 档"更不整齐"，将来有人"统一一下色值"把它抹平回去时，
**对比度会更高、theme 自检更过、像素基线照抄** —— 没有任何其它测试会红。
⚠ 豁免表 `gamutExempt` 是**棘轮**（只准变短，修好了不删也报红）。当前唯一豁免是**深档**：
涨 #FB6D5D 的 L 已贴 sRGB 边界（抬到 0.721 就出域、R 被裁 ⇒ 彩度被动改变，违反判据 ③），
而把跌往下压会让两支在 deutan 空间里**靠得更近** —— 对称解与非对称解各扫一遍都到不了 0.115。
⇒ 那一档的分界只靠 2pt 缝 + 位置 + 宽度三条**结构**通道（与色觉无关，永远在）。

⚠ 图标必须是灰的且很小：它是附属信息，不能跟同一行的主操作（刷新按钮）抢注意力。

**「个股档案」卡：两列各自成块**：指数成份 / 基本面**各占一列**，
用**竖分隔线**划开；每列自上而下是「标题 + ⓘ → 覆盖数字 → **最近刷新时间** → 刷新按钮」，
**按钮在各自列底左对齐**（三列等高，所以按钮横向对齐；左对齐是为了与列内其它内容同一条左边缘）。
⚠ **刷新结果只在浮层提示里说一次** ⇒ 卡上只留**最近刷新时间**（`09-24 09:48`，去掉了年份与秒）。
⚠ 于是"失败原因"只活在 toast 里（基本面失败是 `.error` = **钉住到点不走**，
指数成份"部分未刷新"是 `.warning` = 3.5s）；但**卡上的时间会停在"上次成功"那一刻** ——
"时间没往前走"本身就是"这次没刷上"的信号。
⚠ 两处容易做错的地方：① 报告必须放在弹性空间**之上**，否则"有报告的那列"按钮会被顶上去、
三列不齐；② 三个按钮固定宽度，转圈图标出现时不推动相邻按钮。
⚠ 行尾悬停区**不出现持仓按钮** —— 「持仓 / 编辑持仓」常驻在**名称列**与提醒铃铛并排（见「列表展示」）。

危险操作一律要确认：**删参数版本**、删分组、行内「移出自选 / 清仓」
都走系统确认弹窗（不做长按圆环 —— 桌面鼠标长按既难发现也容易误触，确认弹窗是本平台更清楚的表达）。
⚠ 删除类**不可恢复**（墓碑只保证"重启不补种"）。
⚠ 自选行的右键菜单与悬停按钮**共用同一个确认**（`RowRemoval`）—— 两条入口不再各写一套。
⚠ **移出自选 / 清仓可撤销**：`Cmd+Z` 恢复 —— 移出会把**提醒规则一并恢复**
（只放回票、不恢复提醒 = 用户直到漏一次提醒才会发现）；清仓恢复成本价与股数。
撤销注册在 **Store 层**（3 个移出入口共用一条写路径），不在各视图里各写一份。

### 数据库并发

Swift 侧分三层连接：只读层（主线程专用共享连接）、写层（串行队列独占连接，`BEGIN IMMEDIATE`）、
缓存层（独立只读连接）。与引擎（若在跑）通过 `busy_timeout=30s` + WAL 协调。

## 十三、已知边界

- 次日区间估计的回测为**逐日滚动（无未来函数）**，但模型参数取自同一段历史、测试窗口只覆盖最近样本 → 命中率仍偏乐观；样本越短越不稳
- 调优结果基于已积累的复盘数据，**评估池大小决定可信度**；不自动应用
- 尾盘分时结构依赖分时数据源，数据缺失时该维度自动跳过（不扣分）
- 深度验证受耗时预算约束，超预算候选标注为"未评分"而非"未入选"
- 策略参数针对 A 股主板/创业板/科创板筛选，未覆盖北交所
- **沪深股通（北向）数据不做**：实时/每日北向资金流
  （`kamt/get` 的 `dayNetAmtIn` **恒为 0**，2024-08-19 起取消披露）、
  北向个股持股**只有一期季度快照**（2026-06-30，无历史）且**变动字段全为 null**
  → **粒度与"次日午前"尺度不匹配**（差 60 倍以上）。⚠ 实测证据与穷尽探测过的报表名见
  `docs/specs/README.md`（**别再试一遍**）
- **应用内检查更新（1.0.0 已做）**：Sparkle 2 + GitHub Releases（tag 触发 CI 出 DMG/appcast）。
  但**未走 Apple Developer ID 公证**：首次安装仍会被 Gatekeeper 拦一次（右键打开），
  自动更新本身不受影响（更新包走 EdDSA 校验，不依赖开发者 ID）。
  签名用 `Apple Development` 证书，**一年到期**，续期后新包首次启动会重新问一遍文件夹/钥匙串授权。
  ⚠ 仅 arm64 + macOS 26+；更新通道假设 Release 资产的 `appcast.xml` 匿名可读。
